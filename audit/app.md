# App·웹·설정·테스트 조사

전수 조사에서 확인한 실행 경로와 후속 수정 결과다. 아래 처리표가 각 항목의 최종 상태다.
코드 경로로 확인한 결함과 실행으로 재현한 결함을 구분한다. 사용자 저장·로그는 사용하지 않았다.

테스트 정리: 달력 표시 문자열 전용 파일, 색상 토큰/테두리 검사, 고정 도구 개수와
전체 도구 인자 합집합을 대조하던 부정확한 검사를 제거했다. 저장·명령 결과·폼
정보 공개·오류 복구·실제 게임 전개 검사는 유지한다. 최종 통합 검증 수치는
[REFACTOR-REVIEW.md](../REFACTOR-REVIEW.md)에 기록한다.

이하 내용은 발견 당시의 근거다. 과거 코드 설명을 현재 구현으로 읽지 않는다.

## 중복·표현·정보 경계

- **A08 관리자 편집**: UI·API의 편집 스키마/상태와 엔진의 옛 단일 작업 API가 중복된다. `TeamModal`의 formation을 `undefined`로 보내면 JSON에서 사라져 기존 값을 지우지 못한다. nullable 삭제 계약과 통합 편집 진입점이 필요하다. 단순 표시 테스트 대신 복합 편집 원자성을 남긴다.
- **A09 공통 선수 사실**: `engine/src/app/lookup.ts`와 `app/views/squad.ts`가 계약·배치·가용성·관측을 반복 조립한다. UI·GM 문장까지 같게 만들 필요는 없고, 동일한 사실과 정보 공개 규칙을 공유해야 한다. 경기 결과 화면과 보고서의 `kickOutcome`도 중복이다.
- **A10 협상 UI**: 제안 폼의 시장가는 참값을 사용해 스카우팅 정보 경계를 샌다(Story/negotiation 보고서와 같은 문제). 승인 이력이 하나라도 있으면 다른 조건의 승인 표시까지 숨기는 로직과 이를 고정하는 테스트도 있다.
- **A11 심경 카드**: 사실을 고정 우선순위의 감정 문장으로 단정한다. 새 영입 선수의 이전 출전 부재를 결장으로 읽을 수 있고, 불만의 모든 reason을 다루지 못한다. 사실·GM 기억으로 단순화할 대상이다.
- **A12 표시 호환·갱신**: `scout-report-display.ts`는 거부되는 옛 저장 버전의 숫자형 카드까지 지원한다. `panel-hints.ts`의 서명은 일부 delta/note 변화를 빼므로 새 정보가 같다고 판정될 수 있다. 전자는 삭제 후보, 후자는 실제 갱신 계약이다.
- **A13 경기 UI**: 이벤트의 인물 이름을 현재 경기장 명단에서만 찾으면 교체된 선수의 과거 사건 이름이 빠질 수 있다. `board-drag.ts`의 pointercancel이 drop 경로로 가고 전역 리스너의 언마운트 정리가 없다. 재정 feed의 클릭 가능한 행 안에 `PlayerName` 버튼이 중첩된다. 모두 정적 검토 결과이며 브라우저 재현은 하지 않았다.
- **A14 CSS 소유권**: `common/styles/shell.css`·`shared.css`에 경기·스카우트·협상 전용 스타일이 섞여 있다. import 단방향 검사만으로 CSS 소유권까지 분리되지는 않는다. shell의 `.skill-admin`, `.skill-hint`, `.skill-save`, `.skill-grid`, `.skill-card*`, `.skill-badges`, `.skill-char-count` 약 78행은 CSS 밖 사용처가 없다. 옛 관리자 화면 스타일의 삭제 후보다.
- **A15 반복 UI**: 복사 버튼·복사 완료 타이머, 모달 열림/닫힘과 초점 처리, 수치 fact 표시가 여러 화면에 반복된다. 공통 동작만 공유하고 모든 화면을 범용 설정 객체로 바꾸지 않는다.
- **A16 스크립트**: `fill-nationality.ts`·`fill-squad-roles.ts`의 SPARQL 요청/재시도 경로가 겹친다. `--write`에서 조회 실패·미해결 항목을 기존 값 삭제로 처리할 위험이 있다. 실제 쓰기는 실행하지 않았다. match-cli의 `--games`는 유한한 양의 정수 검증이 필요하다.

## 이번 조사에서 바로잡은 문서

- `docs/overview.md`: BoardAgenda, 실제 실행 시계, 남은 고정 설득·압력·팀토크 규칙, Jev 미연결을 설명한다.
- `docs/architecture.md`: 보드 자유 기대와 남은 체급 기준을 구분하고, 경기 검증의 현재 한계를 명시한다.
- `docs/common/ui/design-system.md`: 실제 서체/CSS 위치, 스켈레톤 펄스, 숫자 서체 적용 범위, 한 줄 말줄임을 설명한다. CSS 구현을 함께 바꿨다는 의미는 아니다.
- `.claude/skills/simulation/SKILL.md`: 현재 사라진 회견 태도 효과표와 보드 점수 공략을 제거했다. 스킬 실행 또는 외부 메시지 전송은 하지 않았다.

폰트는 94개 바이너리의 형식·해시와 CSS 참조를 검사했다. 폰트 CSS의 96개 face·3,497개 Unicode 구간, lockfile의 343개 package·8개 importer는 기계 검증이다. 바이너리·대형 생성 선언을 문장처럼 정독했다고 세지 않는다.

추가로 읽은 `agents/test/app/gm-input.test.ts`의 캐시 검사는 새 기억만 추가한다.
현재 관계·멘토링 변화로 과거 인물 카드가 달라지는 SN-21을 잡지 못한다.
`skill-descriptions.test.ts`는 제공자 스키마·원본 불변성과 유효한 수치 경계를 보존해야 한다.
고정 도구 개수·그룹 개수와 특정 에이전트 목록은 중복 고정값 후보다.
설명에 쓰인 인자 이름 검사는 해당 도구가 아닌 모든 도구 인자의 합집합과 대조하므로,
다른 도구에만 존재하는 인자를 잘못 적어도 통과한다.
