## M-01 — Checkpoint digest does not fingerprint complete simulation state (fix)

`packages/sim/src/live/checkpoint.ts:12-36` hashes positions, selected flight fields, counts and score, but omits player.target/sprinting, full flight destination/receiver/height, restart.at, setPiece, lastPass/lastTurnover, possessionTime/lastShotAt/bench and ledger stats/yellows/substitution counters. These influence future ticks or reported statistics. Two differing states can share a digest without a hash collision. Authority still remains server-side (not a demonstrated client result injection), but divergence detection and digest-based tests are incomplete. Use a canonical complete relevant state serialization (or explicit documented complete fingerprint) rather than expanding hand-picked fields piecemeal. Retain deterministic replay tests; add mutation sensitivity cases in existing sim/live.test.ts and compare complete states in replay assertions.

## M-02 — Global usage meter mixes concurrent games (fix)

`packages/llm/src/usage-meter.ts:228-317` has one module-global sessionLedger/ledgerGameId/warned. `meterLlm` reads budget before await and writes whichever global ledger exists after await. `beginGameUsage(B)` while A awaits resets it; A's completion gets billed to B. Per-game locks do not serialize different game IDs. Capture game-specific ledger per invocation via async context or explicit game identity; keep pure sums and budget/cache tests and add deferred interleaving A/B in usage-meter.test.ts. Sequential switching reset is explicitly documented behavior, a separate product decision.

## M-03 — Independent substitution cap truncates legal friendly/extra-time orders (fix/simplify)

`packages/agents/src/match/tactic-orders.ts:43-50` hardcodes `substitute: 5` and states the rule permits five. Ledger `subLimitsOf` permits friendly 9 and extra-time 6. Both match reader and peace interpreter use TACTIC_CAPS; thus one halftime friendly instruction naming six-to-nine substitutions is truncated before the true ledger validates it. Remove duplicate rule from interpretation cap (use max supported request size / derive current legal limit); ledger remains authority. Keep actual substitution/window/bench tests, replace assertions fixing truncation at five with boundary cases for friendly 9 and extra-time 6.

## M-04 — Sheet acceptance depends on input order, and a missing marking target is silently erased (fix)

`packages/sim/src/sheet.ts:132-224` checks running net/absolute budgets and drops entire lines in order. Example positive +0.035 then negative -0.012 rejects first for net cap, whereas negative first allows both (net .023). Comment says no first-come behavior. Decide an explicit policy: evaluate balanced full sheet and deterministically scale/resolve it, or document ordered priority and return exact dropped lines. Also `targetPlayer` nonexistent becomes undefined without a drop; a mark instruction then loses its target while appearing applied. Preserve budget/entity tests; add order permutation test for balanced sheet and invalid target feedback. Do not remove bounds to grant AI freedom.

## M-05 — Duplicate exponential approximation has false accuracy contract (simplify/fix)

`packages/sim/src/load.ts:88-107` implements separate 14-term Taylor `decay`, while live/dmath.ts owns deterministic `dexp`. Claimed relative error <1e-9 on [0,4] is false: x=2 gives 1.64e-7, x=3 .000185, x=4 .035777 relative error (Python direct formula check). Changing numerical implementation changes saved live outcomes, so preserve version contract. Prefer shared deterministic exponential, validate composition/boundaries and keep workload→condition semantics. This is a concrete formula cleanup, not removal of stamina.

## M-16 — leaderboard tie comparison is non-transitive with missing ratings (fix)

Retain shared award/leaderboard contracts; add permutation/antisymmetry cases to existing leaderboard/records tests.
