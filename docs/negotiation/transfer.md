# 선수 거래와 협상

선수의 **이적·재계약·임대·해지**를 논의하고 결정하는 경험이다. 감독은 원하는 팀을
만들기 위해 조건을 제시하고 사람을 설득한다. 협상에서 한 말과 결정은 다음 연락에
이어지고, 일상으로 돌아가도 관계와 구단 운영에 영향을 남긴다.

## 1. 범위와 책임

| 다루는 일 | 논의하는 내용                                      | 확정되는 것                               |
| --------- | -------------------------------------------------- | ----------------------------------------- |
| 이적      | 영입·매각, 이적료, 개인 조건, 합류 시점            | 소속 변경, 계약, 지급과 약속              |
| 재계약    | 주급, 기간, 역할, 보너스와 약속                    | 기존 계약을 잇는 새 계약                  |
| 임대      | 영입·송출, 기간, 임대료, 급여 분담, 복귀·영입 조건 | 임대 관계와 지급 의무; 원소속 계약은 유지 |
| 해지      | 종료일, 정산금, 지급 일정과 남는 의무              | 계약 종료와 합의된 정산                   |

무소속 영입과 사전 계약은 이적의 조건 차이다. 별도 흥정 시스템을 만들지 않는다.
감독·스태프 고용은 [커리어](../story/career.md)와 [인물](../story/people.md)의 책임이며,
선수 거래 테이블에 섞지 않는다. [스카우팅](scouting.md)도 negotiation이 소유하며, 의뢰·조사·보고는 거래와 구분한다.
보고서를 근거로 실제 연락을 시작하면 해당 상대의 테이블과 거래를 연결한다.

| 담당             | 하는 일                                                                   | 대신 결정하지 않는 것                                       |
| ---------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 메인 `gm`        | 감독의 목표 이해, 명단 관리, 협상 연결, 돌아온 사실로 일상·서사 진행      | 상대의 가격과 계약 수락                                     |
| `negotiation-gm` | 대면·통화·제안서 왕복, 상대의 말과 반응, 평가 요청, 협상 기록과 요약      | 감독이 승인하지 않은 지출·약속, Jev 평가를 벗어난 조건 확정 |
| Jev              | 맥락에 맞는 이적료·주급·조건 묶음과 상대 입장, 필요한 후속 일과 시점 평가 | 실행 도구 호출, 대사 작성, 원장 변경                        |
| 코어             | 권한·참조·계약·재정·날짜 검증, 상태 전이와 지급, 이벤트의 한 번 실행      | 인내 점수·성사 확률·고정 가격 배수로 상대 판단 대체         |
| `app`            | GM 연결, 평가 호출, 시간 진행과 사건 전달, 저장                           | 별도의 협상 규칙                                            |

의존성은 `common → {story, negotiation, match} → app`이다. 거래와 일상은 app을 통해
연결하며, 선수·구단·인물을 도메인마다 복제하지 않는다.

## 2. 상대별 협상 테이블과 협상 방식

**같은 협상 대상자와의 모든 기록은 하나의 협상 테이블에 남는다.** 테이블은 물리적인
장소가 아니라 상대와 이어 가는 협상 기록이다. 대면에서 통화로, 통화에서 제안서로
바뀌어도 새 테이블을 만들지 않는다. 일상으로 돌아가거나 다른 선수를 논의한 뒤에도
같은 상대의 테이블에서 이전 대화·제안·약속을 이어 읽는다.

### 협상 방식은 세 가지다

| 방식   | 경험                            | 남기는 기록                           |
| ------ | ------------------------------- | ------------------------------------- |
| 대면   | 상대와 직접 만나 대화한다       | 발언, 전달한 조건, 반응과 합의        |
| 통화   | 상대와 원격으로 실시간 대화한다 | 통화 내용, 전달한 조건, 반응과 합의   |
| 제안서 | 조건을 작성해 보내고 회신받는다 | 발송한 조건, 수정안, 회신과 검토 일정 |

메일은 제안서의 전달 수단일 수 있지만 별도의 협상 방식이나 기록함으로 나누지 않는다.
방식은 감독의 요청과 현재 장면을 읽은 GM이 정하는 교환의 속성이다. 별도 선택 UI를 두지 않으며 테이블을 나누는 기준도 아니다. 대면 중 제안서를 건네거나
제안서를 받은 뒤 통화하면 각 기록에 방식을 표시하고 같은 흐름으로 연결한다.

### 기록의 범위

- **협상 테이블:** 상대 구단·에이전트 또는 직접 협상하는 선수를 식별하는 지속적인 기록. 같은 상대의
  교환은 방식·선수·거래 종류와 관계없이 시간순으로 함께 남는다. 인물 ID와 대표 권한을
  확인하며 이름이 같다는 이유로 다른 상대의 테이블을 합치지 않는다.
- **거래 건:** 테이블에서 논의하는 선수별 이적·재계약·임대·해지. 대상·종류·방향·
  조건 버전·승인·실행 상태를 구분한다. 같은 에이전트와 여러 선수를 논의해도 각 거래의
  금액·승인·기한은 섞이지 않는다.
- **이번 교환:** 한 번의 대면·통화·제안서 교환. 테이블과 관련 거래를 참조하고,
  방식·일시·실제 발언·제안·답·후속 일정을 남긴다. 종료되어도 테이블 기록은 유지된다.

이는 읽기와 권한의 구분이며 독립 저장 시스템 세 개를 요구하지 않는다. 기존 채팅·
명령·계약 기록을 참조해 공통 타임라인을 만들고, 같은 발언·금액을 복사하지 않는다.

구단은 구단 간 조건을, 선수나 권한 있는 에이전트는 개인 조건을 승인한다. 하나의
거래가 상대 구단과 에이전트의 테이블에 각각 연결될 수 있지만 거래 원장은 하나다.
구단 합의만으로 선수 동의를 만들거나 에이전트의 답으로 이적료를 확정하지 않는다.

감독의 비공개 예산·전략과 다른 상대의 비공개 조건은 공유하지 않는다. 같은 테이블의
기억도 상대가 실제로 아는 범위에서 이어 쓴다. 대표하는 사람이 바뀌면 기록은 보존하고
새 담당자가 읽을 수 있는 범위를 확인한다.

## 3. 감독이 경험하는 흐름

1. **시작한다.** 선수를 지목하거나, 먼저 제안·문의를 보내거나, 받은 연락에 답한다.
   이적 명단에 올리는 일도 입구지만 곧바로 오퍼가 생겼다는 뜻은 아니다.
2. **조건을 주고받는다.** 협상 GM이 해당 상대와 거래 기록을 불러온다. 감독은 가격뿐
   아니라 역할·시점·지급 방식·약속을 두고 설득하거나 조건을 바꾼다.
3. **상대 입장을 확인한다.** Jev가 현재 맥락의 적정 조건과 쟁점을 평가한다. 협상 GM은
   검증된 결과에 맞춰 답장·제안서·대화를 진행한다.
4. **이번 교환을 마친다.** 즉시 답이 끝날 수도 있고 상대 검토, 재연락, 메디컬 등
   후속 일이 잡힐 수도 있다. 감독은 메인 GM 플레이로 돌아간다.
5. **이어 간다.** 연락이 오거나 감독이 다시 찾으면 같은 기록에서 시작한다. 합의된
   조건과 바뀐 사실을 확인하고, 필요한 승인과 절차가 끝나면 코어가 계약을 확정한다.

**먼저 오는 연락도 같은 거래를 연다.** 구단의 보강 필요, 선수·에이전트의 의사,
명단 등재 같은 실제 세계 사건을 app이 협상 GM에 전달한다. 협상 GM은 Jev 평가로
문의·제안의 조건을 만들고 수신 기록을 남긴다. 메인 GM은 도착 요약을 받아 감독에게
알린다. 단순 관심 서술을 이미 받은 제안이나 선수가 승인한 조건으로 바꾸지 않는다.

“3천만 파운드 제안서를 보내”는 협상 화면에 머무를 필요 없이 협상 GM을 거쳐
발송되고 요약이 돌아온다. “에이전트와 직접 얘기할게”는 협상 대화를 활성화한다 — 들어서는
확인 창 없이 같은 턴에 협상 GM이 감독의 말을 받아 첫 장면을 쓰고, 메인 GM은 그 뒤로 말하지
않는다. 두 경로의 조건 평가·기록·확정 규칙은 같다.

계약이 끝나거나 선수가 다른 구단과 계약하면 진행 중인 건을 재검증한다. 새 조건으로
계속할 수 있는지와 거래가 더는 가능한지는 구분한다. 거절·철회 후 다시 접촉할 수
있으며 과거 이력은 남는다. 고정 재접촉 쿨다운이나 영구 배제 규칙은 두지 않는다.

### 예: 제안서를 보내고 일상으로 돌아온 경우

감독이 선수 영입 조건을 제안서로 보내면 협상 GM이 발송과 상대를 기록한다. Jev가
상대의 검토에 시간이 필요하다고 평가하면 그 교환에 답신 예정일을 연결한다.
메인 GM은 보낸 내용과 기다릴 일을 요약받아 훈련·일상을 이어 간다.

예정일에 상대가 분할 지급 대신 즉시 지급을 요구하면 같은 거래에 새 조건이 도착한다.
감독이 답장하면 이전 제안서와 약속을 읽고 계속한다. 가격 합의 후 메디컬이 필요하면
별도의 후속 이벤트가 되고, 소견이 생기면 자동 할인이나 자동 서명 없이 다시 판단한다.
날짜와 요구 조건은 예시 흐름의 고정 규칙이 아니라 해당 평가와 기록이 정한다.

## 4. 스킬 계약

스킬은 GM이 직접 부르는 도구, Jev 결과는 평가
출력, 원장에 적용하는 함수는 코어 명령이다. 세 층을 같은 도구 목록으로 노출하지 않는다.

### 메인 GM

| 스킬                | 입력                                                                                     | 책임과 결과                                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `market_orders`     | 앱이 보관한 감독 원문과 현재 사실                                                        | 이적 명단 등재·해제, 재정 같은 직접 관리 지시. 상대 응답이 필요한 거래는 실행하지 않고 협상 연결 대상으로 반환                 |
| `request_scouting`  | 감독 원문·대상 또는 탐색 조건·질문·선택적 기한                                           | 조사 의뢰·변경·취소. Jev 계획·예정일 보고는 [스카우팅](scouting.md)의 계약을 따름                                              |
| `start_negotiation` | 기존 테이블·거래 또는 상대·선수·거래 종류, 원문 참조, 협상 방식, 대화 이어가기/요청 처리 | 같은 상대의 테이블을 찾아 거래를 연결하고 협상 GM 호출. 대면·통화·제안서를 모두 연결. 대화 이어가기는 메인 GM 턴의 마지막 호출 |
| 공통 조회           | 거래·선수·상대 식별자                                                                    | 진행 상태, 전달된 조건, 승인과 기한, 이전 교환 조회. 비공개 평가의 가격 한계는 감독에게 공개하지 않음                          |

`receive_market_contact`는 세계 쪽에서 시작하는 연락이다. 메인 GM이 실제 이적 명단 등재나
계약 기록을 근거로 상대 구단의 문의를 열고, 협상 평가에 넘긴다. 감독의 발신 명령이나
조건 승인을 대신하지 않는다. 같은 근거와 상대의 연락은 기존 거래를 재사용하며,
문의에는 임의 가격·주급·계약 연수·마감일을 채우지 않는다. 상대의 응답과 조건은
같은 협상 평가·버전 검증을 거치고 감독이 명시적으로 승인해야 계약이 된다.

`market_orders`와 `start_negotiation`은 같은 제안을 중복 실행하지 않는다. 직접 관리와
협상 의도가 한 발화에 섞이면 각각의 결과를 한 턴에 모으되, 제안 발송은 협상 경로
한 곳에서만 일어난다. 같은 상대의 테이블은 재사용하며, 이미 연결할 거래가 있으면 새 거래도 만들지 않는다.

### 협상 GM

| 스킬                   | 입력                                                                        | 책임과 결과                                                                                                                               |
| ---------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `negotiation_orders`   | 해당 거래에 연결된 감독 원문·제안서·명시적 위임                             | 조건 작성·발송·답신, 제안 수락·거절·철회, 확정 지시를 타입 명령으로 검증. 초안과 발송을 구분하며 감독이 승인한 범위만 실행                |
| `evaluate_negotiation` | 거래·상대·조건 버전, 이번 발언                                              | Jev에 상대의 조건·입장을 평가 요청. 검증된 결과와 상대 응답을 기록하고 GM이 표현할 수 있는 사실 반환                                      |
| `accept_negotiation`   | 누가 받아들였는가 — 상대가 우리 최신 조건을, 또는 감독이 상대의 최신 조건을 | 대화에서 양쪽이 같은 조건에 닿았을 때 그 조건 버전으로 합의를 기록하고 서명 카드를 세움. 이미 합의된 거래는 카드만 세움. 서명은 하지 않음 |
| `leave_negotiation`    | 이번 교환의 종료, 기록에 근거한 요약                                        | 필요한 종료 평가가 없으면 같은 평가 경로로 보완하고 후속 일정·GM 전달 요약을 저장. 거래 철회나 계약 수락을 뜻하지 않음                    |
| 공통 조회              | 현재 거래와 상대의 범위                                                     | 조건·계약·재정·선수 사실과 이전 교환 확인                                                                                                 |

협상 GM이 직접 가격과 성공 여부를 써 넣는 판정 스킬은 두지 않는다. 생성한 대사를
다시 파싱해 제안이나 약속으로 만들지도 않는다. 상대의 응답과 발송 기록은 검증된
평가·명령에 연결하며, 감독의 원문을 협상 GM의 문장으로 바꿔 해석하지 않는다.

### 감독의 승인 범위

“가능한 조건을 알아봐”는 문의 권한이고, “이 조건을 보내”는 발송 권한이다.
“이 한도 안에서 마무리해”는 명시한 대상·금액·기간·약속의 범위에서 확정 권한을 준다.
Jev가 적정하다고 판단한 값도 감독의 허가를 대신하지 않는다.

금액이나 조건이 없으면 문의·초안을 진행할 수 있다. 고정 기본 주급·계약 연수로
빈칸을 채워 발송하지 않는다. 한도를 넘어서는 새 요구나 비용은 감독의 결정을 기다린다.
위임도 같은 기록과 평가 경로를 사용하며, 단장 전용 가격 상승 공식은 두지 않는다.

## 5. Jev는 조건을 평가한다

### 입력

- 거래 종류·방향, 현재 날짜와 실제 적용되는 등록 기간, 제안과 합의의 버전.
- 선수의 현재 계약·능력·나이·출전·부상·폼·성장 관측과 희망 역할.
- 당사자 구단의 재정·선수단 필요·대체 자원, 실제로 존재하는 다른 제안.
- 해당 상대의 동기·관계·알려진 기억, 이번 설득, 이전 교환과 약속.
- 계약·등록·소유권 등 반드시 지켜야 할 조건. 감독의 비공개 한도는 상대 판단의
  근거에서 제외하고 실행 권한 검증에 별도로 사용한다.

시장가와 현재 주급은 참고 사실이다. “시장가의 몇 배 안”이 상대의 허용 범위가 되지
않으며, 숨은 참 잠재력이나 감독의 비공개 전략이 상대에게 흘러가지 않도록 문맥을 나눈다.

### 평가 결과

| 결과                    | 의미                                                                              |
| ----------------------- | --------------------------------------------------------------------------------- |
| 상대가 원하는 조건 묶음 | 이적료·주급·계약 기간·지급 일정·임대 분담과 기타 요구를 함께 고려한 구체적 조건   |
| 협의 가능한 대안과 쟁점 | 금액을 낮추는 대신 바꾸려는 조건, 아직 합의하지 않은 부분, 더 알아야 할 사실      |
| 현재 제안에 대한 입장   | 조건 충족에 따른 동의, 수정 제안, 검토 필요, 협의 중단. 단독 수락 확률이 아님     |
| 판단 근거 참조          | 어떤 계약·상황·발언이 조건과 입장을 뒷받침하는지. GM은 이를 사람이 읽을 말로 표현 |
| 선택적 후속 일          | 아무것도 없거나, 다음 응답·재협상·메디컬 등의 일과 일수·목적·담당·필요한 결정     |

조건은 묶음으로 평가한다. 주급을 낮추고 역할을 올리는 것, 이적료와 분할 시점을
바꾸는 것처럼 서로 영향을 주는 항목을 별개의 점수로 합산하지 않는다. 변화 없는
같은 조건은 저장한 평가를 재사용한다. 재접속이나 창 닫기만으로 더 유리한 판정을
다시 뽑지 않는다. 새 제안·발언·중요한 사실 변화가 있을 때 새 버전으로 평가한다.

현재 `GameEvaluator`의 Choice·Score·Noul은 평가 수단이다. 금액·날짜·조건 묶음은
도메인 어댑터가 이 수단으로 구성·검증하는 **출력 계약**이며, API가 임의 JSON이나
산문을 직접 생성한다고 가정하지 않는다. 가격 후보를 임의의 저가·보통·고가 세 칸에
가두지 않는다. 수치 탐색이 필요하면 사실에 근거한 범위를 세분화하고, 경계에 몰릴 때
탐색 범위 부족과 실제 요구를 구별한다. 정확한 금액 표현·일관성은 구현 검증 대상이다.

### 검증과 실패

코어는 유효한 인물·권한·통화·금액·기간·조건의 충돌을 확인한다. 상대가 우리 예산보다
많이 요구하는 것은 허용하되 그 조건을 실행할 수 있다는 뜻으로 처리하지 않는다.
실행 시점의 예산·현금·계약·등록 규칙은 다시 검사한다.

Jev 호출이나 검증 실패는 **처리 대기**다. 임의 가격·자동 거절·기본 일정으로 대신하지
않고, 미처리 평가를 재시도한다. 이미 기록한 응답·일정·지급은 중복 생성하지 않는다.
과거 확정 결과의 재생은 저장한 평가를 사용하며 API를 다시 호출하지 않는다.
교환 종료 평가가 실패해도 일상으로 돌아갈 수 있다. 완료된 교환 기록은 보존하고,
미처리 평가를 이어 하며 예약이 아직 정해지지 않았다는 상태를 분명히 한다.

## 6. 교환 종료와 후속 이벤트

한 번의 교환이 끝나면 Jev가 **필요한 경우에만** 다음 일을 정한다. 대화 중 조건 평가에서는 후속 일정을 생성하지 않는다. 종료 평가는 조건 평가와 구분해 재시도하며 같은 종료 결과를 중복 예약하지 않는다. 현재 대화에서
답을 마칠 수도 있고, 상대가 검토할 시간이 필요하면 며칠 뒤의 답장을 정할 수도 있다.
“매번 이틀 뒤 연락”, 매일 오퍼 추첨, 인내 소진에 따른 강제 종료는 없다.

일수는 게임 날짜 기준이다. 코어는 종료 날짜와 일수를 정확한 실행일로 바꾸고 저장한다.
같은 날 후속 일도 가능하지만 이전 교환이 확정된 다음 처리 단위에서 실행해 재귀 호출을
막는다. 실제 등록 마감·약속한 기한과 충돌하면 자동으로 날짜를 줄이지 않고 재평가한다.

예약에는 이벤트 ID, 거래·교환·조건 버전, 목적, 담당 당사자, 실행일, 선행 조건,
감독 결정 필요 여부와 처리 상태가 필요하다. 미래 응답의 구체적 조건을 확정했다면
그 평가 버전도 연결한다. 나중에 검토하기로 했다면 미래의 수락을 미리 기록하지 않는다.

1. **도래:** app의 시간 진행이 예정일에 도달하면 이벤트를 처리 대상으로 만든다.
   여러 날을 건너뛰거나 시즌이 바뀌어도 중간 예정일을 누락하지 않는다.
2. **재검증:** 제안이 철회·교체되었는지, 이미 계약했는지, 당사자·자격·건강 상태가
   달라졌는지 확인한다. 무효 예약은 취소하고 사실이 바뀐 건은 재평가한다.
3. **진행:** app이 해당 기록으로 협상 GM을 호출한다. 답신·추가 협상은 같은 Jev 경로,
   검진은 실제 선수 건강 정보에 근거한 메디컬 절차를 사용한다.
4. **전달:** 결과를 기록하고 그 날짜에 도달한 턴의 사건과 메인 GM 요약에 반영한다.
   감독 판단이 필요한 경우 시간 진행을 멈추고 해당 거래를 이어 할 수 있게 한다.

단순 발송 확인은 시간 진행을 막지 않는다. 동시 도래 사건은 날짜와 안정적인 순서로
처리하고 하나도 버리지 않는다. 처리 실패는 같은 이벤트의 대기로 남겨 재시도하며,
결정이 필요한 사건을 처리하지 못한 채 그 기한을 넘어가지 않는다. 실시간 경기 중
연락은 보존하고 협상으로 강제 전환하지 않는다.

협상 화면을 닫거나 게임을 다시 열어도 예약은 유지된다. 조건 변경·취소·체결 시에는
관련 예약의 유효성을 함께 갱신한다. 하나의 사건을 tick·GM·UI가 각각 발동하지 않는다.

## 7. 합의, 메디컬, 계약과 원장

**발송 → 답신 → 합의 → 필요한 절차 → 계약 확정**은 서로 다른 사실이다.
모든 거래에 같은 절차를 강제하지는 않는다. 재계약·해지는 보통 구단 간 이적 합의나
메디컬이 필요 없고, 이적·임대는 당사자가 합의한 절차와 등록 규칙을 따른다.

- 승인은 조건의 **정확한 버전**에 연결한다. 가격·역할·조항이 바뀌면 영향을 받는
  당사자의 승인을 다시 받는다. 다른 선수·구단의 승인을 가져다 쓰지 않는다.
- 메디컬은 Jev가 후속 일정으로 선택할 수 있다. 소견은 실제 부상·검진 사실에 근거하며,
  협상 난이도를 위해 부상이나 위험을 새로 만들지 않는다. 소견의 계약상 영향은
  Jev가 재평가한다. 고정 할인율·강행 시 부상 성향 가산·자동 강행은 없다.
- 계약 확정은 필요한 동의, 감독의 승인 또는 유효한 위임, 선행 절차, 현재 실행 자격이
  모두 충족될 때만 코어가 수행한다. 화면 종료나 상대 수락만으로 서명하지 않는다.
- 협상 방의 합의는 협상 GM의 `accept_negotiation`이 기록한다. 합의가 서면 채팅에
  서명 카드가 서고, 감독이 **서명**을 누르면 코어가 그 합의를 계약으로 확정한다.
  방 밖에서 도착한 답신·위임의 동의는 평가 결과가 합의를 기록한다. 평시에서 합의된
  거래를 확정하려면 평시 GM이 `start_negotiation`(continue)으로 그 거래의 테이블을 열고,
  협상 GM이 계약서를 세운다. 합의 상태의 방은 서명이나 돌아가기 전까지 닫히지 않는다.
  평시 GM에게는 계약을 확정하는 명령이 없다.
- 계약·소속·임대·이적 기록·지급 일정·확정 약속은 한 번에 반영한다. 일부만 저장하거나
  재시도로 두 번 지불하지 않는다. 확정 뒤의 변경은 새 계약 변경 또는 별도 정산이다.
- 사전 계약은 서명과 발효일을 나눈다. 발효 전에는 기존 소속과 급여 계약이 유지된다.
  임대는 원소속 계약과 현재 뛰는 팀을 구분하며 합의한 복귀·옵션 조건을 읽는다.
- 일방 해지가 허용되는 경우에도 기존 계약상 정산 의무를 적용한다. 합의 해지로
  가장하거나 지급 의무를 없애는 우회로가 아니다.

수수료·보너스·셀온·되사기·임대 옵션·주급 인상은 명시적으로 합의한 조건만 기록한다.
나이나 이적료 배수로 조항을 자동 부착하지 않는다. 돈과 권리로 실행할 조건은
대상·금액/비율·발동 조건·기한이 구조화되어야 한다. 실행 의미를 아직 정의하지 못한
문장은 논의 기록으로 보존하고, 집행 가능한 조항으로 서명하기 전에 명확히 한다.

금액은 [재정 원장](finance.md)이, 등록 규칙은 [대회](../match/competition.md)가
소유한다. 약속은 원문·대상·기한·승인 출처를 보존하며 story는 그 사실을 읽는다.
기한 없는 기대도 임의의 일수를 붙여 약속 위반으로 만들지 않는다.

## 8. 메인 GM으로 이어지는 이야기

교환 종료, 새 연락 도착, 합의 변경, 계약 확정 때 협상 GM이 기록을 근거로 요약을
남긴다. 요약은 거래 상태를 대신 저장하는 또 하나의 장부가 아니다.

| 요약에 필요한 정보   | 예                                                           |
| -------------------- | ------------------------------------------------------------ |
| 누구와 무엇을 했는가 | 상대 구단·에이전트, 선수, 협상 방식, 테이블·거래·교환 참조   |
| 확인된 진행과 결정   | 보낸 제안, 받은 답, 합의·거절·보류, 현재 조건 버전           |
| 과정에서 남은 일     | 실제로 한 약속, 불편해한 발언, 신뢰를 얻거나 잃은 계기       |
| 다음 행동            | 누구의 답을 기다리는지, 예정된 연락·메디컬, 감독이 결정할 일 |
| 공개 범위            | 감독만 아는 사실, 선수에게 전달된 말, 공개 발표 여부         |

메인 GM은 이 요약으로 훈련장·면담·회견·보드 장면을 이어 간다. 비공개 연락이
자동으로 기사나 라커룸 상식이 되지 않는다. 관계·심경의 변화는 기존 story의 검증된
경로로 한 번 반영한다. 같은 요약을 다시 읽었다고 효과를 다시 주지 않는다.

끝난 거래도 기록을 남긴다. 다른 선수의 협상이나 다음 시즌에 같은 상대를 만나면
관련 있는 과거 교환과 약속을 읽을 수 있다. 상세는 [인물과 기억](../story/people.md).

## 9. 화면과 용어

협상 화면은 **상대·대상 선수·현재 조건과 대화**에 집중한다. 후속 일정은 내부 이벤트 예약이며 목록으로 미리 보여주지 않는다. 예정일에 도달한 턴에 실제 연락이나 검진 소식으로 전달한다. 응답 상황은 상대의 말로 전달하며 포괄적인 “답 대기” 배지는 두지 않는다. 성사 확률과
인내 막대는 두지 않는다. 내부 평가의 유보 가격도 플레이어 정보로 노출하지 않는다.

평가의 처리 대기·판정 근거·조건 요약을 이적 사건 카드로 중복 표시하지 않는다.
제안 조건은 제안 카드와 협상 화면에 모으고, 발송 사실과 실제 회신은 대화로 전달한다.
평가 성공은 발송 확인이 아니며, 후속 예약이 없다는 이유만으로 회신이 없다고 단정하지 않는다.

서명 카드는 합의한 조건(금액·기간·지위·추가 조항)과 **서명** 버튼 하나다. 버튼은 그
거래의 협상 방이 열려 있고 합의 상태일 때만 누를 수 있고, 계약이 확정되면
「계약 확정」으로 바뀐다. 서명은 조작이라 시간을 밀지 않는다.

대면을 전제하는 “자리에 앉기/일어나기” 대신 “제안 보내기”, “답장하기”, “돌아가기”처럼
실제 행동을 쓴다. 협상 화면에 들어서는 확인 창은 없다. 철회는 “제안 철회”로 분리한다.
전송한 제안과 초안, 구단 합의와 개인 합의, 계약 확정과 발효 대기를 구분해 표시한다.

입력창에 첨부해 전송한 제안서는 보낸 메시지에 함께 남는다. 금액·기간·지위·추가 조항은
전송 당시 호출 입력에서 읽으며 현재 협상 조건으로 덮어쓰지 않는다. 제안서만 전송한 경우도
같은 첨부 카드로 표시하고, GM 답변에 같은 발송 카드를 다시 세우지 않는다.

같은 상대의 테이블에는 대면·통화·제안서가 기존 채팅의 과거 메시지로 이어진다.
대화 원문은 `chat`에 한 번만 저장한다. 상대별 테이블과 교환은 식별·방식·거래 참조를 갖고,
별도 연락 원문 배열이나 기록함·필터 UI를 만들지 않는다. 선수 카드·제안서·알림에서
열어도 같은 테이블의 해당 거래로 연결되며, 다른 선수의 조건·승인은 구분한다.
[화면 규약](../common/ui/design-system.md#negotiation-ui)을 따른다.

## 10. 핵심 경험에 필요한 경계

남기는 것은 자유로운 설득, 맥락에 맞는 조건, 계속되는 연락, 감독의 선택과 정확한
계약·재정이다. 관심 단계 사다리, 인내 횟수, 자동 불만·이적 요청 문턱, 성사 확률,
마감일 배율, 고정 재제안 폭, 자동 조항, 위임 가격 공식은 협상 판단 규칙으로 두지 않는다.

이적 명단은 공개된 의사다. 상대의 필요와 현재 사실에서 문의·제안을 만들고 협상 GM의
같은 기록과 평가 경로로 연결한다. 명단 등재 후 일정 일수가 지나면 제안·불만이 반드시
발생하는 규칙은 없다. 선수의 이적 요청·재계약 의사도 실제 이야기에서 나온 결정이다.

우리 팀과의 모든 거래는 이 계약을 따른다. 감독이 관여하지 않는 AI 구단 간 거래는
세계 운영이 묶어 처리할 수 있지만, 매일 거래 수를 맞추기 위한 별도 성공률 표를
핵심 규칙으로 삼지 않는다. 조건의 맥락 판단과 실행 시 원장 검증은 같은 원칙이다.
이 문서가 AI 세계 전체를 매번 대화로 시뮬레이션하도록 요구하지는 않는다.

화면의 참고 이적료는 공개 이동 원장의 가장 최근 이적료다. 기록이 없으면 미확인으로 표시하며, 숨은 능력이나 잠재력으로 금액을 생성하지 않는다. 예산 검색은 금액 미확인 선수를 제외하거나 영입 가능하다고 판정하지 않는다. 계약에 명시된 비율, 실제 등록
기간·자격, 통화 정밀도, 기술적 요청 한도는 유지한다. 이를 상대의 심리·가격을 강제로
움직이는 밸런스 상수와 구별한다. 아직 합의하지 않은 현실 규정을 임의로 덧붙이지 않는다.

## 11. 확인할 동작

- 제안서 발송 후 일상 진행·저장·재접속을 거쳐도 상대와 거래의 이전 기록이 이어진다.
- 같은 상대와 대면 → 통화 → 제안서로 이어도 하나의 테이블에 기록이 순서대로 남는다.
- 같은 상대의 여러 선수 거래는 같은 테이블에서 읽되 승인·조건은 거래별로 분리한다.
- 같은 선수에 대한 서로 다른 상대의 제안은 각 상대 테이블에 남고 비공개 조건을 공유하지 않는다.
- 상대가 감독의 비공개 예산을 알지 못하고, 미승인 조건이 발송·체결되지 않는다.
- Jev는 가격·기간·조항의 묶음을 평가하며 같은 입력의 재시도가 중복 응답·지급을 만들지 않는다.
- 예약일 도달·여러 날 건너뛰기·시즌 전환·동시 이벤트에서도 후속 일이 한 번씩 처리된다.
- 철회·조건 변경·다른 계약 체결 뒤 오래된 답장과 검진이 거래를 되살리지 않는다.
- 평가 실패를 거절·수락으로 바꾸지 않으며, 미처리 건을 이어 할 수 있다.
- 메디컬 소견이나 새 요구가 발생하면 필요한 결정 전에 자동 체결되지 않는다.
- 계약·이적·임대·지급·약속은 원자적으로 확정되고 요약은 그 사실과 일치한다.

테스트는 권한·기한·중복·상태 전이와 금액 보존을 검증한다. 조건의 납득 가능성과
설득의 재미는 맥락이 다른 사례의 평가로 확인한다. 특정 가격 배수나 성공률을 정답으로
고정하는 테스트는 두지 않는다.

조회·흥정 평가의 연락·교환·후속 기록은 이후 GM 서술이 실패해도 보존할 수 있다. 이 부분 저장은 턴 시작 이후 다른 원장이나 평가 근거가 바뀌지 않았을 때만 허용한다. 계약 체결·지급·선수 이동을 포함한 거래는 서술 실패 시 기존 확정 체크포인트로 함께 돌아가며, 평가만 떼어 저장하지 않는다.
