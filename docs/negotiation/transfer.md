# 선수 거래와 협상

감독이 관여하는 이적·재계약·임대·해지는 상대별 협상 기록, Jev 조건 평가,
검증된 합의와 계약 정산으로 진행한다. 인물의 기대와 관계는 캐릭터북에 남고,
금액·소속·계약·지급은 원장이 소유한다.

## 1. 범위와 책임

| 거래                  | 확정되는 사실                                            |
| --------------------- | -------------------------------------------------------- |
| 영입·매각             | 이적료, 소속, 개인 계약, 지급 일정                       |
| 재계약                | 기존 계약 종료와 새 주급·기간·역할·조항                  |
| 임대 영입·송출        | 임대 팀과 원소속, 기간·임대료·급여 분담·합의한 옵션      |
| 해지                  | 계약 종료와 합의한 정산금                                |
| 무소속 영입·사전 계약 | 개인 계약과 발효일; 발효 전 소속·급여는 기존 계약을 따름 |

메인 GM은 감독의 요청을 협상 GM에 연결한다. 협상 GM은 상대의 대화·제안서를
진행하고 Jev 평가를 요청한다. Jev는 조건 묶음·입장·후속 일정을 판단한다.
코어는 당사자·권한·조건 버전·계약·재정·등록을 검증하고 원장을 반영한다.
`app`은 이 역할들과 날짜 진행·저장을 연결한다.

[감독 계약](../story/career.md)과 [스태프 고용](../story/people.md)은 별도 고용 명령을
사용한다. [스카우팅](scouting.md)은 조사·보고 흐름이며 실제 상대 연락을 시작할 때
협상 테이블에 연결한다. 감독이 관여하지 않는 AI 거래의 범위는 §10에 있다.

## 2. 상대별 협상 테이블과 협상 방식

협상 방식은 `meeting`·`phone`·`proposal`이다. 같은 상대와 대표자는 방식이나 선수와
관계없이 연락 테이블을 공유한다. 구단 조건과 개인 조건은 권한에 따라 나눈다.

| 저장 위치                | 소유하는 정보                                              |
| ------------------------ | ---------------------------------------------------------- |
| `negotiationContacts`    | 상대 ID·대표자 ID·구단/선수 측 권한·최초 연락일            |
| `negotiations`           | 선수·거래 종류·상대 구단·제안 라운드·조항·합의·메디컬·상태 |
| `negotiationExchanges`   | 연락/거래 참조·방식·시작/종료일·요약·평가 참조             |
| `negotiationEvaluations` | 조건과 사실의 버전·평가 상태·검증된 결과·오류              |
| `negotiationFollowups`   | 평가/교환/거래 참조·담당·목적·실행일·결정 필요 여부·상태   |
| `chat`                   | 대화 원문과 연락·교환·거래 참조                            |

구단은 이적료·분할 조건을, 선수 측은 주급·기간·역할·개인 조항을 승인한다.
같은 거래가 두 상대의 테이블에 연결되더라도 원장은 하나다. 대표자가 달라지면
별도 연락 식별자를 사용한다. 다른 상대의 비공개 조건과 감독의 위임 한도는
상대 판단 문맥에 넣지 않는다.

## 3. 감독이 경험하는 흐름

1. 선수를 지목해 문의하거나 조건을 보내고, 받은 연락에도 답할 수 있다.
2. 협상 GM이 상대 테이블과 거래를 열어 대면·통화·제안서를 진행한다.
3. 감독의 명시적 조건은 발송 명령으로, 상대의 판단은 Jev 평가로 기록한다.
4. 교환을 마치면 요약과 필요한 후속 일정을 남기고 일상으로 돌아간다.
5. 같은 거래를 다시 열어 조건을 이어 논의하고 필요한 승인을 모아 계약을 확정한다.

`start_negotiation`의 `continue`는 같은 턴에 협상 대화를 시작한다. `dispatch`는
요청을 처리하고 메인 GM으로 요약을 반환한다. 화면을 나가는 것은 제안 철회가 아니다.

세계 쪽 연락은 `receive_market_contact`로 시작한다. 현재 담당 구단이 보유한 선수의
실제 이적 명단 등재 또는 계약을 근거로 다른 구단의 매각·임대 송출 문의를 연다.
같은 근거·상대·거래는 재사용한다. 문의를 열 때 가격·주급·기간·마감일을 채우지 않으며
상대 응답은 협상 평가로 처리한다. 일반적인 관심과 소문은 캐릭터북에 남는다.

## 4. 스킬 계약

| 담당    | 스킬                     | 역할                                              |
| ------- | ------------------------ | ------------------------------------------------- |
| 메인 GM | `market_orders`          | 이적 명단·예산·위임 등 직접 관리 지시를 해석      |
| 메인 GM | `request_scouting`       | 조사 의뢰·변경·취소                               |
| 메인 GM | `start_negotiation`      | 같은 상대의 거래와 교환을 열고 협상 GM 연결       |
| 메인 GM | `receive_market_contact` | 실제 명단·계약을 근거로 세계 쪽 문의 생성         |
| 협상 GM | `negotiation_orders`     | 감독 원문에 따른 조건 제시·답변·철회 등 명령 해석 |
| 협상 GM | `evaluate_negotiation`   | 현재 상대와 조건 버전의 Jev 평가 요청             |
| 협상 GM | `accept_negotiation`     | 최신 조건에 대한 합의를 기록하고 서명 카드 표시   |
| 협상 GM | `leave_negotiation`      | 교환 종료 평가·요약·선택적 후속 일정 저장         |

조회는 실제 조건·계약·재정·선수·이전 교환을 읽는다. 감독 원문, 발송한 조건,
상대 평가와 서사는 서로 구별하며 생성한 대사를 다시 파싱해 계약으로 만들지 않는다.

문의·발송·수락·위임은 각각의 권한이다. 명시한 대상과 금액·기간 한도 안에서만
실행하며, 빈 위임 항목은 무제한 권한이 아니다. 새 역할·조항이나 한도 초과 요구는
감독의 결정을 기다린다. 구단주 판단과 스태프 채용은 직접 스킬
`request_board`·`hire_staff`로 처리한다.

## 5. Jev 조건 평가

평가 입력은 실제 계약·관측 가능한 선수 상태·출전·부상·등록 기간·상대 구단 재정과
선수단·발송 조건·같은 상대의 대화다. 단장·에이전트 정보는 세이브의 최신 캐릭터북을
읽고, 항목이 아직 없으면 초기 인물 정보를 사용한다. 비공개 잠재력과 감독의 위임
한도는 상대 판단의 근거로 제공하지 않는다.

평가 결과는 `agree`·`counter`·`review`·`end` 입장, 조건 묶음·대안·근거 참조와
선택적 후속 일정이다. 제안이 없는 문의에는 `agree`를 선택할 수 없다.

Jev의 Choice·Score를 도메인 어댑터가 금액·기간·역할·조항으로 구성한다.
이적료와 분할은 구단 측, 개인 조건은 선수 측이 평가한다. 금액·기간은 저장 스키마와
지원하는 계약 범위 안에서 검증한다. 시장가나 현재 주급은 참고 사실이다.

`negotiationVersion`은 조건과 관련 사실을 해시한다. 같은 버전의 완료 평가는
재사용하고, 제안·원문·관련 사실·캐릭터북이 달라지면 새 평가가 필요하다.
검증 실패는 처리 대기로 남으며 임의 조건·일정·거절을 대신 기록하지 않는다.
완료된 응답·예약은 재시도에서 중복 생성하지 않는다.

## 6. 교환 종료와 후속 이벤트

후속 일정은 교환 종료 평가에서만 선택한다. 목적은 응답·재논의·메디컬이며,
필요하지 않으면 예약하지 않는다. 종료 날짜와 평가한 일수로 실행일을 저장한다.

시간 진행은 예정일에 도달하면 예약을 처리한다. 조건 버전이 달라진 예약은 취소하고
현재 사실을 재평가한다. 철회·체결된 거래의 예약은 실행하지 않는다. 같은 날 생성된
새 예약은 다음 처리 단위에서 실행하며, 처리 시작 시점의 ID 목록으로 재귀를 막는다.

응답과 재논의는 Jev 평가를, 검진은 실제 건강 상태를 사용한다. 실패한 평가는
대기 상태로 재시도한다. 감독 결정이 필요한 결과는 시간 진행의 정지 사유가 된다.
실시간 경기 중 연락은 기록에 보존한다.

## 7. 합의, 메디컬, 계약과 원장

발송·답신·합의·서명·발효는 각각 별도의 사실이다. 승인은 조건의 정확한 버전에
연결되며 구단 합의만으로 개인 동의를 만들지 않는다.

일반 협상의 `accept_negotiation`은 합의와 서명 카드를 만든다. 감독이 서명하면
코어 `acceptDeal`이 실행 자격·승인·현금·예산·등록·메디컬을 다시 확인한다.
유효한 위임 거래는 후속 처리에서 한도를 검증한 뒤 같은 확정 경로를 사용할 수 있다.
메인 GM은 거래 방을 연결하며 직접 계약을 확정하는 스킬을 갖지 않는다.

메디컬이 예약되어 있으면 결과를 기다린다. 현재 검진은 치료 중인 부상과 예상 복귀일을
소견으로 기록하고, 이상 소견은 조건 영향을 재평가한다. 메디컬이 없는 거래에는
검진 대기를 임의로 만들지 않는다.

계약 확정은 계약·소속·이적·임대·지급 일정·합의 조항을 함께 반영한다.
사전 계약은 발효 전 기존 소속과 계약을 유지하고, 임대는 원소속과 현재 뛰는 팀을
구별한다. 일방 해지는 계약상 정산 의무를 적용한다.

실행 가능한 조항은 `DealTerm`과 계약 스키마가 정의한다. 계약 보너스·공격 포인트
보너스·바이아웃·주급 인상 등은 합의 조건과 실제 발동 사실로 집행한다.
일상에서 한 약속과 그에 대한 인물의 해석은 캐릭터북에 남는다.
금액은 [재정 원장](finance.md), 등록은 [대회 규칙](../match/competition.md)을 따른다.

## 8. 메인 GM으로 이어지는 이야기

교환 요약에는 상대·선수·방식·확인된 조건과 결정·남은 쟁점·다음 행동을 남긴다.
메인 GM은 이 기록을 읽어 일상과 인물의 반응을 이어 가고 `update_character`로
새 사정을 보존한다. 비공개 연락의 공개 범위는 해당 인물이 아는 사실을 따른다.
요약을 다시 읽는 것은 계약이나 지급을 다시 실행하는 일이 아니다.

## 9. 화면과 용어

협상 화면은 상대·선수·조건과 대화를 보여 준다. 감독이 전송한 제안서는 전송 당시
입력을 첨부 카드로 보존한다. 현재 조건으로 과거 첨부를 덮어쓰지 않는다.

합의 상태의 열린 거래 방에서 서명 카드를 사용할 수 있다. 서명은 시간을 진행하지
않으며 확정 뒤에는 계약 확정 상태를 표시한다. 돌아가기와 제안 철회는 별개다.
후속 예약은 내부 기록이며 예정일에 실제 연락·검진 소식으로 전달한다.

대화 원문은 `chat`에 한 번 저장하고 같은 상대의 테이블에서 이어 읽는다.
UI의 레이아웃·첨부·서명 규칙은 [화면 규약](../common/ui/design-system.md#negotiation-ui)이 소유한다.

## 10. AI 구단의 자동 시장과 구현 범위

감독이 관여하지 않는 AI 구단 간 거래는 `runAiTransfers`가 처리하며 Jev를 호출하지
않는다. 주간 계획·일별 정산을 사용하고 선수단 수·포지션·능력·나이·현금·예산·이적창을
검사한다. 시드 난수, 시장가와 구단 계수로 거래 대상과 금액을 정한다.

AI 구단의 `runAiRenewals`는 만료 240일 안의 계약을 검토한다. 기본 일별 확률 0.02에
선수단 내 위치와 나이 계수를 곱하며, 계약은 2–4년·기존 주급의 1.05–1.30배 범위로
만든다. 임대 중이거나 사전 계약이 있는 선수는 제외한다. 대상 선수가 AI 구단과
재계약하면 해당 선수의 열린 사용자 협상을 거절 상태로 닫는다.

이 자동 시장은 사용자가 협상하는 상대의 Jev 평가와 다른 실행 경로다.
현재 세계 운영에는 확률·가격·인원 기준이 남아 있으며 사용자 협상의 조건 한도로
사용하지 않는다. 사용자 거래의 참고 이적료는 공개 이동 원장의 최근 이적료이고,
기록이 없는 선수는 미확인으로 표시한다.

회귀 테스트는 권한 분리, 조건 버전, 승인, 중복 응답·지급, 기한과 예약, 원자적 확정을
검증한다. 실모델의 조건 타당성과 설득 품질은 별도 평가 대상이다.

조회·평가의 연락 기록은 이후 GM 서술이 실패해도, 다른 원장과 평가 근거가 변하지 않은
경우 부분 저장할 수 있다. 계약·지급·선수 이동을 포함한 변경은 확정 체크포인트 단위로
보존하며 평가만 따로 저장하지 않는다.
