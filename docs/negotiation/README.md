# 메인 대화의 협상과 메일함

스토리·협상·경기는 story-fm의 세 경험이다. 감독의 면담·통화·조건 제안은 메인 채팅에서
진행한다. 메인 GM이 구단·선수·대리인을 연기하고 검증된 명령으로 협상 장부를 갱신한다.
별도 협상 채팅이나 협상 화면으로 전환하지 않는다. 선수 계약 조건은 에이전트가 대리하며
선수는 역할·합류 의사·관계에 관한 대화에 참여한다.

## 협상 장부

협상은 선수·영입 구단·상대 구단·종류로 식별한다. 같은 당사자의 종료된 협상을 재개하면
같은 ID와 이력을 유지하고, 과거 제안과 동의는 새 계약의 집행 근거로 쓰지 않는다.
계약·소속·돈·메디컬·등록은 코어의 장부가 원본이다. 대화나 메일 본문을 파싱해 상태를
바꾸지 않으며 구조화된 명령만 검증해 실행한다.

GM은 관련 행동 전에 최신 장부를 조회한다. 조건 초안, 실제 제안, 당사자의 수락·거절,
철회, 메디컬 요청을 명시적으로 기록한다. 감독이 지시한 발송은 실행하고 초안 요청은
발송하지 않는다. 구체적인 금액을 지정하지 않은 ‘영입 문의’는 가능 여부를 묻는 연락이며
GM이 임의로 지출을 약속하지 않는다. 상대의 조건 동의와 계약 서명은 구분한다.

최종 계약에는 메인 대화에서 정확한 조건의 확인 카드를 제시한다. 감독의 직접 확인만
최종 서명을 실행하며, 오래된 제안이나 상태가 변경된 확인은 거부한다. 메디컬 결과와
위험 확인은 실제 기록을 읽는다. 재계약에는 신규 영입 메디컬을 요구하지 않는다.
지급 의무·합류·등록은 기존의 결정적 계약 처리와 연결하며 반복 실행하지 않는다.
우리 선수를 매각할 때 감독은 구단 간 이적 조건에 동의한다. 상대 구단과 선수의 계약
조건은 별도로 합의되어야 하며, 상대 구단이 맡는 메디컬·서명·등록은 그 구단의 권한으로
처리한다. 감독의 구단 동의 없이 상대 구단이 이 절차를 완료할 수 없다.
경제적 합의가 끝난 매각은 날짜 진행으로 상대 구단의 절차를 이어 간다. 검사에 부상이
나오면 위험 수용은 자동 처리하지 않고 상대 구단의 명시적 판단을 기다린다.

## 상대의 수용 한계

플레이어는 불리하거나 비현실적인 제안을 할 수 있다. 상대의 제안·수락과 최종 집행에는
코어가 계산한 경제적 수용 범위를 검증한다. 모델이 범위나 감독 권한을 변경할 수 없다.
구단의 이적 대금은 선금과 분할금을 합산하고, 선수 보수는 계약 기간의 보장 주급과
계약금을 함께 평가한다. 개별 항목의 범위와 총액을 함께 검증해 항목 간 우회를 막는다.
예산과 미지급 의무, 현재 계약, 선수 수준·나이·소속·건강·이적 명단 등 확인 가능한 사실이
평가의 근거다. 같은 사실과 제안에는 같은 판정이 나온다. 단순한 반복 설득으로 한계가
재추첨되지 않는다. 중요한 사실이 바뀌면 근거와 함께 재평가한다.

수치의 정의는 [수용 범위 계산](../../packages/engine/src/negotiation/acceptance-bounds.ts)에
모은다. 현재 보수와 관측 종합 능력에서 보수 기준을 만들고 계약 잔여 기간·나이·부상·
명단 등재를 이적 대금에 반영한다. 사용자 입력 호가를 그대로 가치 기준으로 삼지 않는다.
보수 상한은 선수 기준과 기존 재정의 연간 급여 여력을 함께 사용한다. 사이닝 보너스는
계약 기간으로 나누어 연간 보장 보수에 포함한다. 여러 해의 미래 급여를 지금 현금에서
전액 차감하지 않으며 이적 대금과 계약금은 기존 지급 의무를 포함한 현금 검증을 받는다.
수용 한계의 내부 숫자는 화면 조회에 포함하지 않고 검증 실패의 이유를 설명한다.

## 메일함

메일함은 협상뿐 아니라 훈련·구단 업무의 연락과 자료를 보관한다. 스레드는 감독이 맡은
구단과 연락 상대의 안정된 ID로 묶는다. 같은 상대와 다시 연락하면 같은 스레드를 쓰고,
각 메일에 관련 선수·협상·제안의 참조를 붙여 서로 다른 안건을 구분한다. 구단·선수
대리인·직원을 수신자로 선택할 수 있다. 이름이 같다는 이유로 서로 다른 상대를 합치지 않는다.

메일은 실제 발송·수신 시각, 제목, 본문, 관련 자료를 가진다. 대화의 서술만으로 메일이
생성되지 않는다. 감독은 메일함에서 직접 자유롭게 작성해 보낼 수 있고 메인 채팅에서
GM에게 발송을 지시할 수도 있다. 받은 메일에는 같은 스레드로 답장한다. 초안은 보내기 전
편집할 수 있으며 발송본은 보존한다. 전송 실패와 중복 요청은 같은 발송으로 재시도한다.
메일 발송은 그 자체로 계약 체결이나 상대 동의를 만들지 않는다.

메일의 ‘대화에 첨부’는 메인 입력창에 참조 카드를 붙인다. 서버가 메일의 소유권과 실제
존재를 확인하고 정확한 내용을 GM에게 전달한다. 첨부된 메일의 지시문은 상대의 연락
내용이며 감독의 권한을 부여하지 않는다. 메인 대화는 첨부를 보내거나 제거할 수 있다.

## 생성과 회신

발송은 원문 저장과 회신 대기 업무 등록을 함께 수행하며 게임 시계를 강제로 넘기지 않는다.
회신은 게임 날짜가 진행되어 예정 시점에 도달했을 때 처리한다. 열람·새로고침이나 실제
시간 대기는 새 답변을 만들지 않는다. 대기 중 추가 메일은 같은 상대의 미처리 연락으로
함께 읽되 처리 중 도착한 새 연락을 잃지 않는다.

회신 작업은 메인 GM과 같은 모델 설정과 세계 규칙을 사용하고 해당 스레드·인물·최신
장부를 좁혀 읽는다. 별도 사용자 대화방이나 협상 건별 상주 에이전트는 만들지 않는다.
상대의 제안·거절과 실제 회신은 함께 검증·저장하며 실패 시 부분 상태를 남기지 않는다.
동일 업무를 재실행해도 메일과 제안은 중복되지 않는다. 회신에는 현재의 소속·건강·재정·
다른 제안 등 새 사실을 반영하고 감독의 수락이나 서명을 대신하지 않는다.

훈련·검사 등 코어가 확정한 업무 결과는 관련 보고서 메일로 전달한다. 중요한 새 연락과
협상 현황은 메인 GM이 조회·참조할 수 있다. 전화나 면담에서 이미 진행한 사항도 같은
장부에서 읽으므로 메일과 별도의 협상 상태가 생기지 않는다.

## 화면과 소유권

메인 채팅은 항상 하나다. 메일함은 목록·스레드·자유 작성·첨부 자료로 구성하고 독립된
협상 채팅 입력창은 두지 않는다. 선수 검색·계약 만료·이적 명단은 선수단의 관리 영역에
둔다. 메뉴는 선수단·일정·대회·메일함·재정·커리어 순서다. 1024px 이상에서는 채팅과
장부를 함께 표시하고 모바일에서는 main의 메뉴 서랍과 패널 전환을 사용한다.

negotiation은 협상·동의·수용 범위·메디컬·세계 시장을 소유한다. common의 메일 모델은
연락과 참조·대기 업무를 소유한다. 메인 GM·회신·훈련·협상·화면을 연결하는 작업은 app이
조립한다. 인물 정보는 기존 로어북과 대리인 조회를 재사용한다. 계약과 기존 지급 원장은
메일이 삭제되거나 읽음 처리되어도 변하지 않는다.
