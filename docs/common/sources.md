# 시드 데이터와 출처

시드는 선수·구단의 초기 소속, 계약, 능력과 경기 기록을 제공한다.
카탈로그 값은 새 게임 생성에 사용하며 진행 중인 세이브의 원장을 덮어쓰지 않는다.
외부 선수의 관측값은 참 능력치에 지식 수준별 오차를 적용한다.

## 1. 데이터 범위

카탈로그는 실명 시드와 절차 생성 선수를 함께 사용한다. 새 게임은 이 카탈로그에서
선수·인물·초기 계약을 만들고 이후의 소속·능력·계약은 세이브 원장이 소유한다.
외부 자료의 출처 기록과 게임의 합성 값은 구분한다.

## 2. 출처와 적용 범위

| 자료                         | 사용 범위                         |
| ---------------------------- | --------------------------------- |
| 위키백과 구단·시즌 문서      | 명단·등번호·주장·출전 기록·스태프 |
| Wikidata                     | 선수 QID·생년월일·국적과 외부 ID  |
| fcratings의 EA FC 공개 등급  | 시드 능력치·신체·주발·약발        |
| salarysport                  | 일부 초기 주급 추정               |
| Transfermarkt·Soccerway      | 선별된 부상 이력                  |
| 구단 공식 자료 등 항목별 URL | 구단색·구장 정보                  |

소스가 제공하는 값과 게임에 실제로 저장한 필드는 다르다. 현재 시장가·주급 기대치는
게임 공식의 산출물이며, 시드의 초기 계약 금액과 구분한다. 외부 서비스 가격·이용 가능
여부는 런타임 입력이 아니다.

## 3. 출처 기록

시드 파일과 카탈로그의 출처 주석은 자료의 기준 시점과 수집 범위를 설명한다.
실명·외부 능력치·주급 추정이 포함되어 있다는 사실만으로 배포 권리가 확보된 것은 아니다.
저장소의 자산·출처 기록 범위는 §7을 따른다.

## 4. 시드 적재

### 4.1 시드 갱신 절차 — 두 축을 선수 단위로 잇는다

명단과 능력치는 **서로 다른 시점의 소스**라 클럽으로 이을 수 없다. 위키는 매일
갱신되지만 EA는 게임 출시 시점의 스쿼드에 묶여 있어서, 여름 이적이 끝난 8월에
EA의 소속을 믿으면 이미 떠난 선수가 그대로 남는다. 그래서 **소속은 위키, 사람은
EA**로 나누고 (이름 + 생년월일)로 조인한다.

| 축                        | 소스                                          | 무엇을 정하나                          |
| ------------------------- | --------------------------------------------- | -------------------------------------- |
| 명단·등번호               | 위키백과 구단 문서 `{{Fs player}}` 표         | 누가 이 클럽에 있는가, 몇 번인가       |
| 능력치 6축·신체·주발·약발 | fcratings (EA FC 27)                          | 그 사람이 어떤 선수인가                |
| **위키데이터 QID**        | 위키백과 구단 문서 링크 → 문서 제목           | **조인 키** — 동명이인을 가른다        |
| **생년월일**              | 위키데이터 `P569` (없으면 위키백과)           | 나이, 그리고 QID가 없는 선수의 조인 키 |
| 주급                      | salarysport (EPL만)                           | 초기 계약                              |
| **주장·부주장**           | 위키백과 구단 문서 `{{Fs player}}`의 `other=` | 새 게임의 완장 (§4.1.2)                |
| **계약 지위**             | 직전 시즌 구단 문서의 출전 표                 | 초기 계약의 `squadStatus` (§4.1.2)     |

조인 규약 — **성립하는 조인만 값을 덮는다.**

| 이름                                     | 생년월일                  | 판정                             |
| ---------------------------------------- | ------------------------- | -------------------------------- |
| 성명 완전 일치                           | 연·월·일 일치             | ✅ EA 값을 받는다                |
| 성명 완전 일치                           | 월·일 일치, 연도만 1 차이 | ✅ 받는다 (연도 오타 계열)       |
| 성명 완전 일치                           | 그 외                     | ❌ **다른 사람이다** — 조인 실패 |
| 약칭 한 토막 (`Gabriel`·`Kepa`·`Álvaro`) | 연·월·일 일치             | ✅ 받는다                        |
| 약칭 한 토막                             | 그 외                     | ❌ 조인 실패                     |

⚠️ **대조하는 생년월일은 위키(위키데이터)의 것이지 시드의 것이 아니다.** 시드의
생년월일은 지난 갱신이 남긴 파생물이라 그 자체로는 근거가 못 되고, 근사치가 섞여
있다. 그래서 조인이 성립하면 **생년월일도 위키 확인값으로 함께 바로잡는다.**
그러지 않으면 다음 갱신에서 같은 조인이 또 어긋난다.

#### 위키데이터 QID — 조인 키의 첫째 축

`RealPlayerSeed.wikidataId`가 있는 선수는 **조인 키가 QID다.** 위 표의 (이름 +
생년월일)은 QID가 없는 선수에게만 남는다 — 그 조합에는 사람을 가르지 못하는 자리가
있기 때문이다(§4.1.1).

채우는 경로는 하나뿐이고, 한 번에 여러 선수를 처리한다.

| 단계 | 무엇을                                                                                 |
| ---- | -------------------------------------------------------------------------------------- |
| 1    | 구단 문서 위키텍스트에서 **1군 절**의 `{{Fs player}}`(별칭 `football squad player`) 행 |
| 2    | 행의 `name=[[문서 제목\|표시명]]`에서 **문서 제목**                                    |
| 3    | 제목을 시드 행에 잇는다 — 같은 구단 안에서 `nameEn`이 정규화 후 일치하는 행            |
| 4    | 제목 → `action=query&prop=pageprops&ppprop=wikibase_item` (50개씩) → QID               |

**문서 제목이 동명이인을 이미 갈라 둔다** — `Vitinha (footballer, born March 2000)`과
`Vitinha (footballer, born February 2000)`은 서로 다른 문서다. 그래서 3단계의 이름
일치가 구단 안에서 유일하면 QID까지 1:1이 성립한다.

⚠️ **표시명이 같아도 제목이 다르면 다른 사람이다 — 시드의 `nameEn`은 제목을 쓴다.**
세비야 35번은 표에 `[[Iker Ortín Muñoz|Iker Muñoz]]`로 실려 있어 표시명이 오사수나의
`Iker Muñoz`(Q116603156)와 같다. 표시명으로 실으면 두 사람이 (이름 + 생년월일) 키를
나눠 갖고, 한쪽 생년월일이 바로잡히는 순간 서로를 덮는다 (`seed-join.test.ts`의
중복 축이 잡는다). 제목이 붉은 링크면 QID는 없는 채로 남지만, 제목은 그때도 있다.

⚠️ **없으면 없는 채로 둔다.** 위키 문서가 없는(붉은 링크) 아카데미 자원과 링크가
동음이의 문서를 가리키는 행은 QID 없이 남는다 — 시드 2,847명 중 93명이 그렇다.
주발·부상 이력과 같은 원칙이다(§7). 지어낸 QID는 없는 것보다 나쁘다: 이 키의
목적이 위키 재대조 없이 중복을 잡는 것인데, 가짜 키는 정확히 그 반대를 한다.

⚠️ **QID를 검증하는 것은 생년월일이 아니라 그 행이다.** QID의 근거는 구단이 자기
문서에 실은 그 링크다. 생년월일은 반대 방향으로 흐른다 — QID가 정한다(바로 아래).

#### 생년월일은 `P569`가 정한다

**QID가 있으면 그 선수의 `birthdate`는 위키데이터 `P569`다.** 여기에는 이름 매칭이
끼지 않으므로 오조인 위험이 없고, 시드의 옛 값은 지킬 근거가 없다 — 지난 조인이
남긴 근사치가 섞여 있어 몇 살씩 어긋난 값도 그 안에 있다.

조회는 QID를 묶어 던진다 — SPARQL `VALUES` 250개씩, `p:P569/psv:P569`로 **시간값과
정밀도와 순위를 함께** 받는다. `wdt:P569` 한 줄로는 아래 표의 두 예외가 보이지
않는다.

| `P569`의 상태                        | 시드가 하는 일                             |
| ------------------------------------ | ------------------------------------------ |
| 일(日) 정밀도 값 하나 (순위 반영 후) | **덮는다**                                 |
| 문장이 없다                          | 옛 값 유지                                 |
| 정밀도가 연(年)·월(月)               | 옛 값 유지 — `YYYY-01-01`은 정보가 더 적다 |
| 서로 다른 값이 같은 순위로 둘 이상   | 옛 값 유지 — 근거가 하나로 좁혀지지 않는다 |

순위는 `PreferredRank`가 있으면 그것만 보고 `DeprecatedRank`는 버린다.

⚠️ **예외 셋을 추정으로 메우지 않는다.** 연도만 아는 값으로 덮으면 월·일이 있던
자리가 자리표시자로 바뀌고, 갈리는 두 값 중 하나를 고르면 그 선택은 근거가 아니라
취향이다. QID가 없는 93명도 같은 이유로 이 절이 닿지 않는다.

지금 QID 2,754명 중 **2,718명이 `P569` 그대로**이고, 나머지 36명(문장 없음 2 ·
정밀도 미달 10 · 값이 갈림 24)은 옛 값으로 남아 있다.

⚠️ **생년월일을 덮으면 `potential`을 다시 잰다** — 나이가 대역을 정하기 때문이다
(아래 "그리고 `potential`을 다시 잰다").

#### 자리표시자 생년월일 — `birthdateApprox`

`YYYY-01-01`은 **연도만 알고 월·일은 조사가 닿지 않았을 때 채운 자리**인 경우가
있다. 실제 1월 1일생과 생김새가 같아서, 표시하지 않으면 둘을 영영 가르지 못한다.

그래서 **`-01-01`인 시드는 `RealPlayerSeed.birthdateApprox`를 반드시 명시한다.**

| 값      | 뜻                                             |
| ------- | ---------------------------------------------- |
| `true`  | 자리표시자 — 연도만 근거가 있고 월·일은 모른다 |
| `false` | 대조해서 실제 1월 1일생임을 확인했다           |
| 없음    | 허용하지 않는다 (`seed-join.test.ts`가 잡는다) |

표식이 없으면 "조사했는데 1월 1일이더라"와 "조사하지 않았다"가 같은 값으로
보인다. 주발·부상 이력과 같은 원칙이다(§7): **모르는 것은 모른다고 적는다.**

⚠️ **`birthdateApprox: true`인 생년월일은 조인 키가 아니다.** 위 조인 표의 판정에
쓰지 않고, 조인 실패의 기본값인 "옛 값 유지"도 이 값에는 적용하지 않는다 — 지킬
사실이 없기 때문이다. 확인된 날짜(위키·위키데이터, 없으면 EA)가 나오면 **그대로
덮고 표식을 지운다.**

자리표시자는 나이만 흐리는 게 아니라 성장·노화 곡선의 입력까지 어긋나게 한다
(`packages/engine/src/story/players/development.ts`) — 연도까지 틀린 경우가 있어 두 살이 어긋나기도 한다.
확인 기준은 좁다: 리그·TM 기록의 생일이 **출생지 공란인 DB 자리표시자 형태**면
확인으로 치지 않는다. 지금 시드에 `-01-01`은 14명이고 그중 13명이 확인된 실제
1월 1일생, 마디 마칼루(헤타페) 한 명만 `true`다.

**조인 실패의 기본값은 옛 값 유지다.** 이름이 같다는 이유로 값을 덮으면 동명이인
한 사람의 레코드가 다른 사람에게 실린다. 옛 값은 낡았을 뿐이지만, 남의 값은 틀렸다.

⚠️ **월·일까지 어긋나는데 연도만 맞다고 받는 완화는 쓰지 않는다.** 동명이인은
생일의 월·일에서 갈리므로, 그 완화는 6축이 통째로 20 가까이 뒤집히는 오조인을
그대로 통과시킨다.

⚠️ **옛 값이 이미 남의 값인 경우가 있다.** 조인 실패라고 무조건 되살리면 안 된다 —
옛 6축 자체가 다른 나라 하위 리그 동명이인의 레코드일 수 있다. 옛 값을 되살리기
전에 그 값도 실물과 대조한다.

⚠️ **EA의 생년월일에도 오류가 있다.** 그래서 조인 실패가 곧 시드가 틀렸다는 뜻은
아니다 — 시드가 실제 생일을 갖고 EA가 틀린 경우, 그 선수는 앞으로 EA 갱신이 닿지
않는다. **예외 목록으로 뚫지 않는다.** 예외 목록은 위 완화 규칙의 다른 이름이고,
낡은 값이 남의 값보다 낫다.

⚠️ **EA의 신체도 틀린다.** 조인이 성립했더라도 **실물과 어긋나는 게 확인되면 위키
확인값이 이긴다** — 사비 시몬스 체중 58kg(키 179에 BMI 18.1로 프로 대역 밖),
고스기 게이타 168cm(실제 172). 신체는 사람을 가리는 축이기도 해서, 자리에 있을 수
없는 값은 조인 성공의 증거가 아니라 실패의 증거다(비카리오 160cm 골키퍼).

조인 실패로 EA 값을 버릴 때도 **위키에서 확인한 신체는 넣는다.** 값이 없으면
카탈로그가 능력치로 파생하는데(`catalog.ts` `physiqueOf`), 확인된 실측이 있는데
지어낸 값을 쓸 이유가 없다.

마지막에 **"한 EA 레코드는 한 선수만"**이라는 1:1 제약으로 남은 충돌을 끊는다.

**그리고 `potential`을 다시 잰다.** EA가 덮는 것은 6축이고 잠재력은 그 자리에
남는데, 6축이 바뀌면 파생 OVR이 움직여 간격이 혼자 벌어지거나 뒤집힌다.
**생년월일도 같은 것을 움직인다** — 대역은 나이별이라 하루 차이로도 칸이 바뀐다.
갱신이 끝나면 나이 대역(→ [player.md](player.md) §6.5)으로 전수를 재고 **벗어난
선수만** 경계로 접는다 — 대역 안의 값은 사람이 매긴 판단이라 일괄 재계산하지 않는다.

조인이 성립한 뒤에도 **값이 뒤집히면 조인을 의심한다.** 갱신 뒤에 자동으로 걸리는
검사가 넷이다 (`packages/engine/test/common/seed-join.test.ts`). 주급·프로필·잠재력·키의
문턱은 현재 시드에서 이상 후보를 찾는 휴리스틱이며, 모든 축구 선수에게 성립하는
불변식은 아니다. 위반은 조인 오류인지 실제 예외인지 출처로 다시 확인해야 한다.

| 무엇을 보나                             | 왜 그 축인가                               | 잡히는 예                            |
| --------------------------------------- | ------------------------------------------ | ------------------------------------ |
| 주급 백분위 − 파생 OVR 백분위           | 주급(salarysport)은 EA와 **무관한 출처**다 | 외데고르 주급 98%·OVR 5%             |
| 자리와 프로필의 모순                    | 자리와 축 분포의 이례적 조합을 찾는다      | 칸첼리에리가 수비수 프로필로 뒤집힘  |
| 잠재력−OVR 간격이 나이 대역 상한을 넘음 | 잠재력도 6축 조인과 독립인 수기 판단값이다 | 산투스 OVR 61 · 잠재력 87            |
| 자리별 키 하한                          | 자리별 신체 분포에서 이례적 값을 찾는다    | 비카리오 194→160cm, 고메스 188→167cm |

⚠️ **셋째 축은 갱신 뒤에 `potential`을 함께 재야 성립한다.** `potential`은 그때의
6축에 맞춰 손으로 매긴 값이라, EA 실측이 들어와 OVR이 정당하게 내려간 선수는
잠재력만 낡은 채 남는다. 그 낡은 값을 나이 대역으로 접어 두어야
(→ [player.md](player.md) §6.5) 이 축이 **주급 괴리와의 AND 없이 단독으로** 선다 —
AND로 좁히면 주급 축이 없는 EU 2,192명이 통째로 사각지대가 된다.
**갱신 절차의 마지막 단계가 대역 재측정인 이유가 이것이다** — 건너뛰면 가드가
자기가 만든 잡음에 묻힌다.

#### 국적은 `P1532`가 정한다 — 갈리면 대표팀 기록이 가른다

**축구에서 국적은 나라가 아니라 협회다.** 잉글랜드·스코틀랜드·웨일스·북아일랜드는
한 시민권을 나눠 갖는 네 협회이고, 홈그로운도 비EU 쿼터도 대표팀도 전부 협회 단위로
걸린다. ISO 3166-1은 그 넷을 담지 못하므로(`GBR` 하나뿐이다) 코드는 **FIFA 3자 협회
코드**를 쓴다 (`packages/domain/src/common/nationality.ts`) — 대부분의 나라에서 ISO alpha-3와 같고,
갈리는 자리에서 축구 쪽을 따른다(`GER`·`NED`·`SUI`·`POR`·`DEN`·`CRO`·`KVX`).

조회 경로는 QID 하나뿐이라 이름이 끼지 않는다 — 생년월일 `P569`와 같은 결이다.
`scripts/fill-nationality.ts`가 돌리고(`pnpm fill-nationality [--write]`), **시드의
`nationality`를 적는 것은 이 스크립트뿐이다.** 손으로 고친 값은 다음 실행이 되돌린다.

사다리는 네 칸이고, 위 칸이 답하면 아래로 내려가지 않는다.

| 사다리 | 무엇이 정하나                                                  | 지금 시드           |
| ------ | -------------------------------------------------------------- | ------------------- |
| ①      | 스포츠 국적 `P1532` — 순위 반영 후 값이 하나                   | 2,637명             |
| ②      | 갈리면 **성인 대표팀 출전 수**(`P54` → `Q135408445` · `P1350`) | 29명                |
| ③      | 그래도 갈리면 시민권 `P27`이 확인된 협회로 좁힌다              | 35명                |
| ④      | 그래도 갈리면 **코드 오름차순**                                | 28명                |
| —      | `P1532`도 `P27`도 없음 · QID 없음 → 시드를 비운다              | 25명 + 93명 = 118명 |

⚠️ **연령별 대표팀은 세지 않는다**(②). 프랑스 U-21을 거쳐 세네갈 A대표가 된 선수의
협회는 세네갈인데, 연령별을 함께 세면 유스 경기 수가 A매치를 이긴다. 그래서 성인
대표팀 항목(`Q135408445`)만 본다 — 그 통계가 아예 없으면 ③으로 내려간다.

⚠️ **④까지 온 선수는 A매치를 뛴 적이 없다** — 현실에서도 어느 협회를 택할지 정해지지
않은 자리다. 그래서 코드 오름차순은 주장이 아니라 **표기 규칙**이고, 두 협회를 모두
싣는 것이 그 자리에서 할 수 있는 전부다. 판정에는 영향이 없다: `isEuNational`이 두
칸을 함께 보므로 등록 자격은 순서와 무관하다.

**둘째 국적은 하나만 싣고, 여럿이면 EU 협회를 먼저 싣는다.** 이 칸이 게임에서 하는
일이 정확히 등록 자격 판정이라, 하나만 실을 수 있다면 규정을 가르는 쪽이 실린다.
영국 시민권(`Q145`)은 협회가 아니므로 이미 고른 협회가 영국 안이면 그 협회의 몫으로
접히고, 아니면 `ENG`로 선다.

⚠️ **협회가 아닌 항목은 버린다** — 카탈루냐·과들루프·마르티니크(FIFA 회원이 아니다)와
유고슬라비아 연방 공화국(사라진 나라)이 `P27`·`P1532`에 섞여 온다. 지어낸 코드보다
나쁜 것이 **아무 규정도 읽지 못하는 코드**다. 리포트가 버린 항목을 건수와 함께 낸다.

**빈 채로 두지 않는다 — 이것만 생년월일과 다르다.** 등록 규정도 대표팀도 "국적을
모르는 선수" 갈래를 따로 들 수 없어서, 하나가 비면 그 위의 규칙이 통째로 서지 못한다.
그래서 위 118명은 **시드를 비워 두고 카탈로그가 그 클럽 협회로 세운다**
(`deriveNationality` — `packages/engine/src/common/world/catalog.ts`). 절차 생성 선수도 같은 규칙이다: 이름을
이미 리그 국적의 풀에서 받으므로(`packages/engine/src/common/data/names.ts`), 국적만 따로 굴리면 잉글랜드 이름을
단 세네갈 사람이 스물몇 명씩 선다. **이것은 실측이 아니라 부채다**(§7) — 시드가
채워지면 파생은 물러난다.

전수는 시드 2,847명 중 2,729명(둘째 국적 462명)이고, 카탈로그 5,317명은 파생까지
합쳐 전원이 국적을 갖는다 (`checkPlayerNationality`가 새 게임 앞에서 센다).

#### 절이 명단을 정한다 — 등번호가 아니라

시드에 들어가는 것은 **1군 절(`현 스쿼드`·`First-team squad`)의 행 전부**다.
그 밖의 절 — 임대(`Out on loan`)·2군(`Reserve team`)·유스(`Under-21s and
Academy`·`Primavera`·`B team`)·`Other players under contract`·`Returning from
loan` — 의 인원은 넣지 않는다.

⚠️ **등번호가 없다고 유스가 아니다.** 1군 표 맨 아래에는 아직 번호를 못 받은
1군 선수가 `no=`를 비운 채 실린다 — 래시퍼드(맨유)·헨더슨(첼시)·퓔크루크
(웨스트햄)가 그 자리에 있다. 번호로 거르면 이들이 통째로 사라진다. **번호가
없는 것은 번호일 뿐 소속이 아니다** — 그 행은 명단에 넣고 번호만 비운다
(§4.1.1 마지막 항목이 그때의 번호 규칙이다). 세리에A 네 구단(아탈란타·라치오·
파르마·사수올로)은 아예 표 전체가 번호 없는 알파벳순이다.

유스를 거르는 것은 **절**이지 번호가 아니다. 1군 절에 없는 선수는 그 클럽에
없다 — 다만 위 절들을 모두 훑은 뒤에 판정하고, 그래도 안 보이면 선수 개인 문서의
`currentclub`으로 한 번 더 확인한다 — 아카데미에 실명을 쓰지 않는 이유는
[people.md](../story/people.md) §2에 있다.

#### 새로 넣는 선수 — 생년월일이 문턱이고, 능력치는 자리 기준치다

**생년월일이 확인되지 않으면 넣지 않는다.** 위키 개인 문서에도 위키데이터에도
없는 사람은 조인 키가 없어서, 다음 갱신이 그를 같은 사람으로 알아보지 못한다.
그 자리는 카탈로그가 클럽당 40명 하한을 메우며 합성 가명으로 채우므로 스쿼드
깊이는 그대로다 — 확인되지 않은 실명을 넣는 쪽이 잃는 것이 더 크다.

**능력치는 fcratings가 원본이고, 닿지 않으면 자리 기준치다.** 자리 기준치는
**그 구단 같은 포지션군 실선수의 축별 중앙값**이다 — 지어낸 값이 아니라 이미
시드에 있는 값에서 나오고, 같은 입력이면 같은 값이 나온다. 이때 신체·주발·약발은
**비운다**: 카탈로그가 파생하는 자리이고, 비어 있다는 것 자체가 "조사가 닿지
않았다"는 표식이다(`birthdateApprox`와 같은 원칙). `potential`은 중앙값을 쓰되
파생 OVR과의 간격을 나이 대역 안으로 접는다(→ [player.md](player.md) §6.5).

⚠️ **자리 기준치는 실측이 아니라 부채다.** 다음 fcratings 갱신이 덮어야 할
자리이고, 덮이기 전까지 그 선수의 6축은 "이 구단 이 자리의 보통"일 뿐이다.

#### 4.1.1 소속 판정 — 한 선수는 한 구단에만 있다

**임대 선수는 임대처(host) 스쿼드에 넣는다.** 시드에는 임대 관계를 담는 필드가
없어 소속이 곧 그 시즌 그가 뛰는 곳이고, 그것을 정하는 표는 임대처 구단 문서의 현
스쿼드다(`other=on loan from …`). 모구단 문서의 `other=at X until …` 행은 계약의
기록이지 소속의 근거가 아니다 — 그 행을 따라 모구단에 남기면 임대처 스쿼드에서
그만큼 깊이가 빠지고, 모구단은 뛰지 않는 선수의 급여를 이중으로 진다.

**두 구단 문서가 같은 선수를 함께 실으면 한쪽이 낡은 것이다.** 갱신일이 문서마다
달라 이적한 선수가 옛 구단 표에 며칠 더 남는다. 이때는 선수 개인 문서의
`currentclub`이 가른다 — 구단 문서 둘의 다수결이 아니다.

⚠️ **이름이 같아도 생년월일이 다르면 다른 사람이다.** 비티냐 둘(2000-02-13 PSG ·
2000-03-15 제노아), 무사 디아라 둘(2000-11-10 알라베스 · 2003-01-22 말라가),
알렉스 히메네스 둘(2005-05-08 피오렌티나 · 2005-04-19 오사수나)이 실재한다. 생일이
19일밖에 안 떨어진 동명이인이 있어서 **(이름 + 생년월일)은 중복을 다 잡지 못한다** —
생일이 어긋난 중복이 그 검사를 그대로 통과한다. QID가 그 자리를 메운다: 세 쌍 모두
서로 다른 위키 문서이고, 곧 서로 다른 QID다. `seed-join.test.ts`가 지키는 불변식은
넷이다.

| 불변식                                  | 무엇을 잡나                                                                                      |
| --------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 한 QID는 시드 전체에서 한 행뿐이다      | 생일이 어긋난 중복 — 두 구단에 걸친 것도, 한 구단 안의 것도. **시드만 읽어서 갈린다**            |
| QID는 `Q` + 숫자다                      | 오타 난 키는 다른 사람의 키가 아니라 아무의 키도 아니라서, 중복 검사를 조용히 빠져나간다         |
| 같은 (이름 + 생년월일)이 두 구단에 없다 | QID가 없는 93명에게 남은 축 — 복붙으로 생긴 중복                                                 |
| 한 클럽 안에서 등번호가 겹치지 않는다   | 선수를 옮길 때 조용히 깨지는 자리 — `ensureSquadNumbers`는 빈 번호만 채우고 충돌은 그대로 남긴다 |

**옮긴 선수의 등번호는 옮긴 구단 표의 번호를 받는다.** 표가 번호를 주지 않으면
(`no=`가 빈 임대 행) 옛 시드 번호를 유지하되, 그 번호를 이미 표에 실린 선수가
쓰고 있으면 **표 쪽을 남기고 옮겨온 쪽을 비운다**(§7 등번호 항목과 같은 규칙).

**주급은 구단을 따라가지 않는다.** `weeklyWage`는 salarysport가 EPL 선수 단위로
집계한 추정치라, 선수가 EPL 밖으로 나가면 그 축이 닿지 않는다 → 값을 지우고
모델 추정(`estimateSquadWages`)에 맡긴다. EPL 안에서 구단만 바뀌면 값을 유지한다.

#### 4.1.2 완장과 계약 지위 — 구단이 공표한 것만 적는다

두 축 모두 **시드가 갖고, 없으면 파생이 선다**. 갱신 경로는 하나뿐이다 —
`pnpm fill-squad-roles`(`--write`로 시드에 적는다). 손으로 고친 값은 다음 실행이
되돌리므로, 고쳐야 할 것이 있으면 위키를 고친다.

| 축          | 소스                                           | 기준 시점  |
| ----------- | ---------------------------------------------- | ---------- |
| 주장·부주장 | 구단 문서 `{{Fs player}}` 행의 `other=captain` | 2026-08-18 |
| 계약 지위   | 직전 시즌(2025-26) 구단 문서의 출전 표         | 2026-06-30 |

**구단 문서는 손으로 적지 않는다.** 팀 id → 문서 제목 표를 96줄 들면 클럽이 이름을
바꾼 날 조용히 어긋난다. 스크립트가 시드 선수의 QID로 위키데이터 `P54`(현 소속)를
물어 후보를 모으고, **그 문서를 실제로 열어 시드 명단과 겹치는 사람 수를 세어**
확정한다 — 대표팀·2군·낡은 소속이 섞여 와도 겹침이 가른다. 그래도 안 풀리는 클럽만
스크립트의 `ARTICLE_OVERRIDES`에 적는다(2026-09 기준 여섯: 노팅엄·오세르·파더보른·
트루아·엘버스베르크·브레스트).

**주장 — 조인 키는 등번호다.** 같은 시점의 같은 문서에서 오는 값이라 번호가 유일한
키로 성립하고, 표기가 갈리는 이름(`Gabriel`·`Rodri`)을 지나간다. 임대 나간 선수의
완장 표기(`other=... on loan to ...`)는 그 구단의 것이 아니라 버린다.

- 2026-09 갱신 기준 **100클럽 중 92클럽이 주장을, 46클럽이 부주장을** 받는다.
  나머지는 위키 표가 완장을 달지 않은 클럽이고, 그 자리는 비워 둔 채
  `initialCaptainOf`가 배치에서 파생한다([people.md](../story/people.md) §5-1).
- ⚠️ **지어낸 완장은 없는 것보다 나쁘다.** 실명 시드에 사실 아닌 직책을 적으면 그것이
  곧 인물평이 되고, §7의 NIL 부채가 사실에서 서술로 넘어간다.

**시드의 역할 추정 — 근거는 직전 시즌 선발 비율이다.** 현재 수집기의 분류는 0.70 이상이면
`key`, 0.50 이상이면 `starter`다. 이 값은 관측에 근거한 시작 정보이며 협상에서
합의한 역할이나 불만 판정 비율로 사용하지 않는다([인물](../story/people.md)). 분모는 **선발의 합 ÷ 11**로 잰 그 시즌 경기 수다 —
최다 출전 선수의 경기 수를 쓰면 그가 빠진 경기만큼 분모가 작아져 모두의 비율이
부푼다. 조인 키는 **이름**이다: 등번호는 여름마다 자리를 바꿔서, 지난 시즌 5번의
기록이 올해 5번을 단 사람에게 간다.

- 2026-09 갱신 기준 **100클럽 중 35클럽**이 지위를 받는다 — `key` 175명 ·
  `starter` 137명, 구단당 여섯에서 열넷.
- **왜 서른다섯뿐인가** — 선발과 교체를 갈라 적은 직전 시즌 문서가 그만큼이다. 영어
  위키의 시즌 문서는 `30+1`(선발 30 · 교체 1)로 적는 쪽과 출전 수만 적는 쪽이
  섞여 있고, 후자(맨시티·맨유·브렌트퍼드)는 **선발 수라는 답을 갖고 있지 않다.**
  그런 표에서 비율을 재면 교체로만 나온 선수가 주전으로 서므로 통째로 버린다.
  프랑스·스페인·이탈리아 구단 상당수는 영어 시즌 문서 자체가 없다.

##### 시드의 역할 정보 범위

현재 수집기는 근거가 있는 `key`·`starter`만 기록한다. 선발·교체를 구분할 수 없는
자료로 역할을 추측하지 않으며, 관측 비율에 해당하는 선수를 구단별 인원 상한으로
잘라 내지 않는다. 이 정보는 초기 선수단을 설명한다. 자동 출전 기대·불만 문턱이나
계약상의 역할 약속을 만들지 않는다.

## 5. 데이터 통합 — 조인 키 전략

소스마다 선수 ID 체계가 달라 "같은 선수"를 잇는 게 통합의 핵심 작업이다.
**Wikidata를 ID 브리지**로 쓴다.

| 소스                        | 식별자                           | 연결 방법                                         |
| --------------------------- | -------------------------------- | ------------------------------------------------- |
| EA FC 데이터셋              | `sofifa_id`                      | Wikidata 보유 외부 ID(`P`속성)로 1차 매핑         |
| Transfermarkt               | `tm_player_id`                   | 〃                                                |
| OpenFootball / API-Football | 팀명·선수명 문자열               | 없는 건 **이름 + 생년 + 소속클럽** 퍼지 매칭 보강 |
| **Wikidata**                | `QID` (+ sofifa/TM ID 종종 보유) | **허브 역할** — 여기를 기준으로 나머지를 연결     |

**시드가 이미 그 축을 들고 있다** — `RealPlayerSeed.wikidataId`가 위키백과 구단
문서에서 온 QID이고(§4.1), 시드 2,847명 중 2,754명이 갖는다. 새 소스를 붙일 때
이름 매칭부터 다시 시작하지 않고 이 열에서 출발한다.

지금 코어의 선수 키는 `gamePlayerId`(세이브)와 시드의 `wikidataId`이고, 소스 간
매핑 테이블은 아직 없다 — 새 소스를 붙이는 날 `packages/domain`에 하나로 둔다.

## 6. 현재 적재와 산정 경로

실선수 명단과 6축·GK 시드는 `packages/engine/src/common/data/`에 있다.
`packages/engine/src/common/world/catalog.ts`가 시드를 읽고 `deriveAxes`로 16축 카탈로그를 만든다.
브라우저에 공유하는 스키마와 순수 규칙은 `packages/domain`이 갖고, 새 게임이
카탈로그를 세이브로 복사한다. `packages/agents`는 그 상태를 읽어 서사와 검증 대상
판정을 낸다.

`packages/engine/src/common/world/synthesis.ts`에는 체급·깊이·자리·나이 기반의 결정적 산정 모델이 있다.
이는 실측 경기 통계로 학습한 AI 모델이 아니며, 현재 실선수 시드의 능력치를 자동으로
대체하는 적재 경로도 아니다. `attribute-model` 하네스가 두 분포를 비교한다.

## 7. 자산과 출처 기록

| 자료             | 현재 저장과 처리                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 선수 시드        | `packages/engine/src/common/data/`의 실명 카탈로그. 자료에 없는 선수는 절차 생성 경로로 구성한다.                            |
| 능력치·신체·주발 | 외부 시드와 파생 값을 구분한다. 결측값 처리와 생성 모델은 [player.md](player.md)에 정의한다.                                 |
| 초기 주급        | `RealPlayerSeed.weeklyWage`가 있으면 초기 계약에 사용한다. 없으면 `wageExpectationOf`로 산정한다.                            |
| 부상 이력        | `injury-history.ts`의 QID별 기록을 새 게임의 부상 원장으로 펼친다. 표에 없는 선수는 미조사 상태이며 초기 성향은 평균값이다.  |
| 홈그로운         | 경력 원자료 대신 `deriveHomegrownCountry`의 결정적 생성 규칙을 사용한다. 실선수의 등록 이력을 입증하는 자료는 아니다.        |
| 인물             | `coach-seeds.ts`·`owner-seeds.ts`·`world-figures.ts`의 실명과 생성 이름을 사용한다. 로어북의 성격·동기·대사는 게임의 서사다. |
| 구단색           | `club-colours.ts`가 색 값과 항목별 출처 URL을 소유한다.                                                                      |
| 구장             | `club-profile.ts`의 이름·수용인원을 재정 모델이 읽는다.                                                                      |
| 구단 문장        | 클럽 ID에서 결정적으로 생성한다. [팀 표현](team.md) §3.1을 따른다.                                                           |
| 서체             | `apps/web/public/fonts/`의 Pretendard Variable·Barlow Condensed와 각 폴더의 `OFL.txt`.                                       |

`pnpm pseudonymize`는 선수·구단·구장 표시 이름의 결정적 변환 도구다. ID를 유지하며,
이 도구의 존재가 현재 시드의 가명화를 뜻하지는 않는다. 진행 중인 세이브는 저장된
이름을 사용한다. 도구의 입력·출력은 `scripts/pseudonymize.ts`에 정의한다.

## 8. 시드 검증

- QID와 생년월일로 동명이인을 구별하고 선수별 소속 중복을 검사한다.
- 국적·등번호·주장·계약 지위는 §4의 출처와 우선순위를 적용한다.
- 실제 자료가 없는 항목은 결측·추정·생성을 구분한다.
- 생성 능력치 분포는 `pnpm balance attribute-model`로 확인한다. 밴드는
  [밸런스 하네스](balance-harness.md)의 descriptor가 소유한다.
- 실명·서체·구단색 등의 출처와 동봉 파일은 각 카탈로그·자산 폴더에서 확인한다.
