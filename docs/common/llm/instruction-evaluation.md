# 직접 지시 평가 — 합성 입력과 전체 턴

`packages/agents/harness/instructions-eval.ts`는 GM 스킬 뒤에서 실행되는 역할별
지시 평가의 수동 하네스다. 전술 예제는 `tactic-orders`, 이적 명단 예제는 `finance-orders`,
등번호 예제는 `training-orders`의 명령 목록과 실제 문맥만 사용한다. 명령 목록은 해당 역할의 실제 카탈로그에서 읽는다.

기본 실행은 오프라인이며 `--live`가 있어야 TypeSafe를 호출한다. `--turn`은 별도의
새 메모리 게임에서 실제 `runGmTurn`을 실행한다. 선택적 `--match-turn`은 새 경기에서
공간 시뮬레이터를 최대 600초 진행하고 실제 관측한 흐름을 가진 전술 턴을 실행한다.
경기 사례는 압박 축, 특정 선수 맨마킹, 왼쪽 공격 집중 효과를 각각 확인한다.
연속 효과는 대상·방향과 양의 적용 강도를 확인하며 특정 수치를 정답으로 정하지 않는다.
관측 길이는 보고서에 남기며 저장된 사용자 경기 흐름으로 가장하지 않는다.
`--case match-mark` 또는 `--case match-left-focus`로 한 경기 사례만 재현할 수 있다. 전체 턴의 판정·코어 journal은 메모리에서
수집해 지정한 출력 보고서에만 남기며, 사용자 trace 디렉터리를 열지 않는다. 양성 입력은 GM이 전술 스킬을 골라
`tactic-orders`의 Jev 사용량과 코어 적용을 남기는지, 실행 금지·일반 대화는 Jev 호출
없이 끝나는지 확인한다. 세이브나 사용자 로그·데이터를 읽고 쓰지 않는다.

합성 예제 다섯 개는 컴파일러의 출력만 확인한다. 해당 역할을 GM이 정확히 고르는지는
전체 턴에서 별도로 본다. 출력이 맞아도 대표 사용자 정확도나 기존 경로 대비 개선을
뜻하지 않으며, 서사 품질의 블라인드 평가는 별도다. 보고서의 소스 파일 SHA-256은
같은 게임 버전 안에서 수정된 코드로 실행한 결과를 구별한다.

## 실행

```bash
pnpm exec tsx packages/agents/harness/instructions-eval.ts \
  --out /tmp/instructions-offline

pnpm exec tsx packages/agents/harness/instructions-eval.ts \
  --live --turn --match-turn --out /tmp/instructions-live
```

모델은 `config/llm.yml`만 읽는다. 앱 `.env.local`은 `--live`에서만 로드하고 키는
기록하지 않는다. 출력은 새 디렉터리의 `report.json`·`summary.md`이며 `.log`·`.data`
안이나 그곳으로 향하는 심볼릭 링크 아래에는 쓸 수 없다. 기존 디렉터리도 재사용하지
않는다. 차단·실패·기대 불일치는 종료 코드 1과 보고서에 남는다.

Jev 단가는 설정의 확인된 입력 단가와 무료 출력을 사용한다. GM 가격은 실행자가
[공식 가격](https://ai.google.dev/gemini-api/docs/pricing)에서 확인해서
`--gm-input-usd-per-million`·`--gm-output-usd-per-million`·
`--gm-cached-input-usd-per-million`으로 준다. 생략하면 전체 턴 비용은 미확정이다.
실제 계정 청구액과는 구분한다.
다른 에이전트가 함께 불리거나 미보고 사용량·가격이 있으면 전체 비용은 미확정이다.

컴파일러 보고서는 각 평가 단계와 내부 재시도의 보고된 토큰을 실패까지 합산한다.
전체 턴은 `withGameUsage`의 에이전트별 장부를 읽으며 실패한 호출의 보고된 토큰도
남긴다. 이 장부의 호출 수는 HTTP 재시도 횟수가 아니며, 제공자가 보고하지 않은
실패 토큰은 알 수 없다. 실행 시간이 빠르거나 다섯 예제가 맞았다는 사실만으로
정확도·비용·전체 턴 지연의 개선을 주장하지 않는다.

## 사례와 판정

직접 해석은 강한 압박, 내려서 공간 지키기, 실행 없는 논의, 이적 명단 등재,
등번호 배정을 각 역할의 명령 목록으로 평가한다. 전체 턴은 실제 `runGmTurn`으로
GM의 스킬 선택과 코어 반영까지 확인한다. 경기 사례는 압박·맨마킹·왼쪽 공격 집중이다.

전술은 요청한 방향과 허용된 명령·필드만 적용됐는지 확인한다. 실행을 보류한 발언과
일반 대화는 상태 변화와 Jev 호출이 없어야 한다. 서로 다른 유효한 전술 해석은
수동 검토 대상이며 특정 강도 하나를 정답으로 고정하지 않는다.

보고서는 실행 소스 지문, 모델 설정, 요청·평가 상태의 해시, 질문·응답, 코어 진단과
실패를 함께 보존한다. 여러 실행에서 성공한 사례만 골라 하나의 성공률로 합치지 않는다.
합성 사례의 통과는 명령·상태 전이의 증거이며 한국어 전반이나 서사 품질의 보장은 아니다.
