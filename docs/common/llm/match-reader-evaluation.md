# 경기 판독기 비교 — 기록 입력과 채택 조건

**시트 강도를 산문 호출 뒤 Jev로 평가하는 분리는 채택하지 않는다.** 기록 입력 6개의
실호출에서 두 경로 모두 검증을 통과했지만 평균 지연은 줄지 않았고 정가 환산 비용은
5.4% 늘었다. 한국어·축구 판독의 블라인드 품질 검토도 끝나지 않았다. 이 결과는
시트 분리 후보에 대한 것이며, 감독 지시를 직접 명령으로 옮기는 별도 경로의 성능이나
품질을 입증하지 않는다.

## 범위

비교한 입력 계약은 **게임 버전 12.0.0의 판독기 시범**이다. 산문 LLM은 포인트·시트
후보의 대상과 동작·감독 명령을 만들고, Jev는 각 후보의 강도 분포만 평가한다. 기대
강도는 기존 연속 `step`으로 돌아간다. 시트 구조와 명령 전체를 Jev가 생성한다고
주장하지 않는다. 명령 해석을 분리한 현재 실행 그래프와 이 비교의 계약을 혼동하지
않는다. 현재 역할은 [에이전트 책임](agents.md)에 있다.

기준 경로는 산문 한 호출, 후보는 산문 다음 Jev 평가다. 감독 발화가 없는 입력에서는
명령 출력 스키마를 제외하고 응답의 명령도 무시한다. 두 경로는 동일한 기록 입력과
명령 스키마를 쓰며 포인트·시트에는 비교 시점의 도메인 스키마를 쓴다. 과거 프롬프트를
그대로 재현한 실험은 아니다.

## 현재 확보한 증거

2026-09-27 13:36 UTC에 끝난 비교다. 보존된 `calls/*.json`을 읽기 전용으로 읽었으며
원문·키·게임 식별자는 저장소에 복사하지 않는다. 아래 실호출 시간은 판독 함수 진입부터
검증된 결과 반환까지다. 산문·평가와 재시도를 포함하지만 매치 GM 중계와 브라우저 재개는
포함하지 않는다. 백분위는 nearest-rank이고, 입력 6개에서 p95는 최댓값이다.

| 항목                            | 보존된 과거 판독 호출 | 기준 경로 재생 | 산문 + Jev 재생 |
| ------------------------------- | --------------------: | -------------: | --------------: |
| 입력 / 성공 / 실패              |             9 / 8 / 1 |      6 / 6 / 0 |       6 / 6 / 0 |
| 산문 호출 / Jev 요청 시도       |                미확정 |          6 / 0 |           6 / 6 |
| 판독 지연 p50                   |               2,732ms |     2,666.69ms |      3,059.13ms |
| 판독 지연 p95                   |              10,509ms |     4,299.39ms |      3,658.12ms |
| 산문 입력 / 출력 토큰 합        |        64,706 / 5,280 | 47,237 / 3,042 |  47,207 / 2,832 |
| Jev 입력 / 출력 토큰 합         |                     — |          0 / 0 |    40,693 / 474 |
| 정가 환산 총비용 USD            |                미확정 |     $0.0217761 |    $0.022951206 |
| 시트 구조 Jaccard               |        기준 정답 아님 |      비교 기준 |         0.08696 |
| 대응된 시트 강도 MAE (0–3 눈금) |        기준 정답 아님 |      비교 기준 |          0.9925 |
| 명령 완전 일치 (감독 발화만)    |        기준 정답 아님 |      비교 기준 |             4/4 |
| 한국어·축구 판독 블라인드 품질  |                미검토 |         미검토 |          미검토 |

- 쌍별 평균 지연 차이는 후보가 **17.37ms 더 느림**이다. p95 하나가 낮아진 것으로
  개선을 선언하지 않는다. 비용은 **5.4% 증가**했다. 기준과 후보의 캐시 읽기·쓰기는 0이다.
- 빈 시트 입력 하나는 평가자를 호출하지 않는다. 나머지 입력 5개에서 Jev 요청은
  재시도 하나를 포함해 6번이다. 보고된 모든 시도의 토큰을 합산했다.
- 시트는 기준 24줄·후보 26줄 중 4줄이 대응되고 20줄·22줄은 각각 미대응이다.
  포인트 문장의 표현 차이도 미대응을 만들므로 이 수치는 정확도나 우열이 아니다.
  강도 MAE는 대응된 4줄만의 값이다. 명령 4/4 일치도 정답 보장은 아니다.
- 판독 원문 9건 중 성공 8건에는 중복 입력 2건이 있어 고유 재생 입력은 **6개**다
  (감독 발화 4, 발화 없음 2). 수집된 전체 에이전트 원문은 비교 시작 시점 83건이다.
- 판독 사실 로그는 127건이다: 킥오프 23, 사건 92, 하프타임 9, 지시 3. mock 실행도
  포함될 수 있고 사실과 호출은 일대일이 아니므로 9/127을 포집률로 쓰지 않는다.
- 과거 호출 버전은 7.0.0·9.0.0이다. 실패 1건에는 모델·토큰 기록이 없고 당시 적용
  가격도 없어 비용은 미확정이다. 과거 지연은 저장된 호출 하나의 시간이며 재시도를
  합친 판독 전체 시간으로 간주하지 않는다.

산문 모델은 설정의 `gemini-3.5-flash-lite`, 평가자는 `jev-1.13.0`이다.
[Google 공식 가격표](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite)의
일반 유료 가격을 2026-09-27 확인했다: 백만 토큰당 입력 $0.30, 출력(사고 포함) $2.50,
캐시 읽기 $0.03. Jev는 [공식 모델 문서](https://docs.typesafe.ai/models)의 입력 $0.042,
출력 무료를 쓴다. 위 비용은 보고된 사용량을 이 정가로 환산한 값이며 실제 계정 청구서나
무료 등급·크레딧을 반영한 결제액이 아니다.

## 다시 실행하기

```bash
pnpm exec tsx packages/agents/harness/match-reader-eval.ts \
  --logs /Users/dhoonjang/local/story-fm/apps/web/.log \
  --out /tmp/reader-eval-offline
```

기본은 네트워크 없는 인벤토리다. 실제 비교는 다음처럼 실행한다. 가격 인자는 실행
시점의 공식 가격을 다시 확인한다. **현재 코드·설정으로 재측정하는 명령**이며 위 버전
12.0.0의 결과를 현재 프롬프트의 결과라고 바꾸어 읽지 않는다.

```bash
pnpm exec tsx packages/agents/harness/match-reader-eval.ts \
  --logs /Users/dhoonjang/local/story-fm/apps/web/.log \
  --out /tmp/reader-eval-live \
  --live --baseline-agent history-compactor \
  --input-usd-per-million <현재-선택한-모델의-입력-단가> \
  --output-usd-per-million <현재-선택한-모델의-출력-단가> \
  --cached-input-usd-per-million <현재-선택한-모델의-캐시-단가>
```

`--out`은 새 디렉터리를 사용한다. 원본 로그 안이나 그곳으로 향하는 심볼릭 링크
아래로는 출력할 수 없고 기존 결과 파일도 덮어쓰지 않는다. 결과는 `report.json`과
`summary.md`다. 로컬 실측 산출물은
`/tmp/story-fm-867-live-paired-rounded-20260927/`에 있다. 보고서는 게임 버전과
산문 시도별 시스템 프롬프트·스키마 SHA-256을 남기며 원문 입력을 복사하지 않는다.
원문 경로와 쌍별 산출·확률은 로컬 보고서에서만 연결한다.

실호출은 `TYPESAFE_API_KEY`와 현재 판독기 제공자의 키가 필요하고 앱의 `.env.local`은
실호출 때만 읽는다. `--limit N`으로 입력 수를 제한할 수 있다. 모델은 `config/llm.yml`만
읽는다. `--baseline-agent`는 해당 역할의 모델·시한·토큰 한도만 빌리며, 역할의 실제
프롬프트나 스킬을 실행하지 않는다. 비교 프롬프트는 `harness/reader-baseline.ts`에
고정되어 있다. 보고서는 선택한 설정도 남기므로 과거의 실행 한도와 구분할 수 있다.
가격이 없거나 실패 요청의 토큰이 보고되지 않으면 비용은 미확정이다. 현재
가격을 과거 기록에 소급하지 않는다.

먼저 실행할 경로를 번갈아 캐시 순서 영향을 줄인다. 실패도 지연·성공률·알려진 토큰
합에 남기며, 실패한 쌍이나 실호출 차단 사유가 있으면 종료 코드는 1이다. 에러 종류와
어댑터가 만든 고정 진단 문구만 보고하고 제공자 본문·키는 출력하지 않는다. SDK 내부
재시도에서 보고하지 않은 사용량까지 안다고 가정하지 않는다.

## 읽는 법과 채택 게이트

시트 구조는 포인트 문장을 공백 정규화한 뒤 대상·모양·부호·동작이 같은 줄끼리
일대일 대응한다. 미대응 줄 수·Jaccard와 대응 줄의 강도 MAE를 함께 본다. 같은 뜻을
다르게 쓴 문장은 미대응이므로 자동 점수가 품질 판정은 아니다. 빈 시트끼리의
일치율도 미정이다. 명령 비교는 키 순서를 정규화하되 명령 배열 순서를 보존한다.
감독 발화 없는 턴의 빈 명령 일치는 명령 품질 통계에서 제외한다.

채택에는 대표성 있는 기록 입력과 양 경로 성공 결과가 필요하다. 포인트의 사실 근거,
이득과 대가, 지시 충실도, 선수 능력·자리·역할·체력·적응·폼을 가리는 오류를 사람이
경로 이름을 가린 상태에서 검토한다. 실패율과 쌍별 지연, 두 단계의 총비용까지 함께
비교한다. 현재 6개 입력과 미완료 품질 검토로는 이 게이트를 통과하지 못한다.
단일 Jev 요청의 빠른 응답이나 타입 유효성만으로 채택하지 않으며, 측정하지 않은
매치 GM·브라우저 구간까지 정지점 개선이라고 일반화하지 않는다.
