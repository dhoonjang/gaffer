# 경기 판독기 비교 — 기록 입력과 채택 조건

**Jev는 평가용 시범이며 기본 경기 경로에 채택하지 않는다.** 직접 API 키가 없는
현재 환경에서는 비교 실호출·품질 판정·지연 개선을 검증할 수 없다. 구현과 오프라인
검증이 끝난 것은 실측 완료와 다르다.

## 범위

산문 LLM은 포인트·시트 후보의 대상과 동작·감독 명령을 만든다. Jev는 각 후보의
강도 분포를 평가한다. 기대 강도는 기존 연속 `step`으로 돌아간다. 시트 구조와 명령
전체를 Jev가 생성한다고 주장하지 않는다. 임의 금액·약속·심경을 유한 선택지로
바꾸는 별도 표나 에이전트 층은 없다.

기본 판독기는 한 호출이다. 감독 발화가 없는 정지점·킥오프에서는 명령 출력 스키마를
제외하고 응답의 명령도 무시한다. 명령 산출 정규화는 다른 네 해석기와
`parseOrdersReport`를 공유한다. 세 경험의 역할과 유지 근거는
[에이전트 책임](agents.md#9-현재-호출-책임과-jev-시범)에 있다.

## 현재 확보한 증거

2026-09-27 로컬 기록을 읽기 전용으로 검사한 결과다. 원문·키·게임 식별자는 저장소에
복사하지 않는다. `pnpm log --facts match.reading`으로 사실 로그를 확인하고,
하네스는 보존된 `calls/*.json`의 원문 요청을 평가 입력으로 사용한다.

| 항목                        | 보존된 과거 판독 호출 | 현재 기본 경로 재생 | 산문 + Jev 재생 |
| --------------------------- | --------------------: | ------------------: | --------------: |
| 호출 관측 수                |       9 (실패 1 포함) |                   0 |               0 |
| 호출 지연 p50               |               2,732ms |              미측정 |          미측정 |
| 호출 지연 p95               |              10,509ms |              미측정 |          미측정 |
| 입력 / 출력 토큰 합         |        64,706 / 5,280 |              미측정 |          미측정 |
| 비용                        |                미확정 |              미측정 |          미측정 |
| 시트 구조 일치율 / 강도 MAE |        기준 정답 아님 |           비교 없음 |       비교 없음 |
| 명령 일치율 (감독 발화만)   |        기준 정답 아님 |           비교 없음 |       비교 없음 |
| 한국어·축구 판독 품질       |                미검토 |              미검토 |          미검토 |

- 전체 에이전트 호출 원문은 81건이다. 판독 호출 9건 중 성공 8건은 중복 입력 2건을
  포함하므로 재생 가능한 고유 입력은 **6개**다(감독 발화 4, 발화 없음 2).
- 판독 사실 로그는 127건이다: 킥오프 23, 사건 92, 하프타임 9, 지시 3. mock 실행도
  포함될 수 있고 사실과 호출은 일대일이 아니므로 9/127을 포집률로 쓰지 않는다.
- 과거 호출 버전은 7.0.0·9.0.0이다. 모델은 `gemini-3.5-flash-lite`이며 실패 1건에는
  모델·토큰 기록이 없다. 당시 적용 가격도 없어 비용을 만들어 내지 않는다.
- 과거 지연은 **저장된 호출 하나**의 시간이다. 재시도까지 합친 판독 전체의 시간이나
  매치 GM 중계·브라우저 재개를 포함한 정지점 전체 대기는 아니다.
- 실제 `--live` 사전 점검 결과는 `Missing TYPESAFE_API_KEY`다. 설정과 Google 키는
  확인됐지만 쌍 비교를 시작하지 않았으며, 성능 향상·채택의 근거가 없다.

## 다시 실행하기

```bash
pnpm exec tsx packages/agents/harness/match-reader-eval.ts \
  --logs /Users/dhoonjang/local/story-fm/apps/web/.log \
  --out /tmp/reader-eval-offline
```

기본은 네트워크 없는 인벤토리다. `--out`은 새 디렉터리를 사용한다. 원본 로그 안이나
그곳으로 향하는 심볼릭 링크 아래로는 출력할 수 없고, 기존 결과 파일도 덮어쓰지 않는다.
결과는 `report.json`과 `summary.md`다. 실호출은 `TYPESAFE_API_KEY`와 현재 판독기
제공자의 키를 준비하고 **`--live`를 추가**한다. 앱의 `.env.local`은 실호출 때만 읽는다.
`--limit N`으로 입력 수를 제한할 수 있다. 모델은 `config/llm.yml`만 읽는다.

현재 산문 모델의 확인된 가격은 `--input-usd-per-million`, `--output-usd-per-million`,
필요하면 `--cached-input-usd-per-million`으로 준다. 이 가격은 과거 기록에 소급하지
않는다. 가격이 없거나 실패 요청의 토큰이 보고되지 않으면 비용은 미확정이다.
TypeSafe 공개 입력 가격은 설정에 있고 출력 요금은 0이다
([공식 가격과 API](models.md#6-jev-시범--생성과-확률-평가의-경계)).

동일 원문·명령 스키마에 현재 프롬프트·현재 포인트/시트 스키마를 써서 기본·시범을
짝으로 실행한다. 먼저 실행할 경로를 번갈아 캐시 순서 영향을 줄인다. 원문 요청의
옛 프롬프트를 재현한 것과 구분한다. 시범 시간은 산문·Jev 두 단계와 재시도를 합하며,
실패도 지연·성공률·알려진 토큰 합에 남긴다. SDK 내부 재시도에서 보고하지 않은
사용량까지 안다고 가정하지 않는다.

## 읽는 법과 채택 게이트

시트 구조는 포인트 문장을 공백 정규화한 뒤 대상·모양·부호·동작이 같은 줄끼리
일대일 대응한다. 미대응 줄 수·Jaccard와 대응 줄의 강도 MAE를 함께 본다. 같은 뜻을
다르게 쓴 문장은 미대응이므로 자동 점수가 품질 판정은 아니다. 빈 시트끼리의
일치율도 미정이다. 명령 비교는 키 순서를 정규화하되 명령 배열 순서를 보존한다.
감독 발화 없는 턴의 빈 명령 일치는 명령 품질 통계에서 제외한다.

채택에는 대표성 있는 기록 입력과 양 경로 성공 결과가 필요하다. 포인트의 사실 근거,
이득과 대가, 지시 충실도, 선수 능력·자리·역할·체력·적응·폼을 가리는 오류를 사람이
경로 이름을 가린 상태에서 검토한다. 실패율과 쌍별 p50·p95 지연, 두 단계의 총비용까지
함께 비교한다. 단일 Jev 요청의 빠른 응답이나 타입 유효성만으로 채택하지 않는다.
지연이 줄어들지 않거나 판독 품질이 떨어지면 기본 경로를 유지한다. 이 하네스가
측정하지 않는 매치 GM·브라우저 구간까지 정지점 개선이라고 일반화하지 않는다.
