# 메일함

메일함은 감독이 구단 밖·안의 사람과 주고받는 연락의 원장이다. 협상의 조건과 자료,
훈련·검사 보고, 구단 업무의 연락이 같은 스레드 구조에 쌓인다. 협상의 장부 자체는
[transfers.md](../team/transfers.md)가 소유하고, 메일은 그 협상을 참조할 뿐 계약이나
동의를 만들지 않는다.

## 1. 스레드와 수신인

스레드는 감독이 맡은
구단과 연락 상대의 안정된 ID로 묶는다. 같은 상대와 다시 연락하면 같은 스레드를 쓰고,
각 메일에 관련 선수·협상·제안의 참조를 붙여 서로 다른 안건을 구분한다. 구단·선수
대리인·직원에게 연락할 수 있다. 받는 사람은 자유롭게 입력하며 구단·전체 선수·연락 가능한
담당자를 자동완성으로 제안한다. 선수 이름은 그 선수의 대리인 연락처로 연결한다.
발송 시 서버가 현재 저장의 이름·별칭과 실제 연락 권한을 검증하여 수신인 ID를 확정한다.
후보를 누르지 않아도 한 상대가 명확하면 발송한다. 동명이인 등 후보가 여럿이거나 상대를
찾지 못하면 초안을 유지한 채 확인할 후보나 오류를 보여주고 발송하지 않는다.
명시적으로 고른 상대와 답장은 해당 ID를 유지하며, 받는 사람을 수정하면 다시 판별한다.
이름이 같다는 이유로 서로 다른 상대를 합치지 않는다.

메일은 실제 발송·수신 시각, 제목, 본문, 관련 자료를 가진다. 대화의 서술만으로 메일이
생성되지 않는다. 감독은 메일함에서 직접 자유롭게 작성해 보낼 수 있고 메인 채팅에서
GM에게 발송을 지시할 수도 있다. 받은 메일에는 같은 스레드로 답장한다. 초안은 보내기 전
편집할 수 있으며 발송본은 보존한다. 전송 실패와 중복 요청은 같은 발송으로 재시도한다.
메일 발송은 그 자체로 계약 체결이나 상대 동의를 만들지 않는다.

메일의 ‘대화에 첨부’는 메인 입력창에 참조 카드를 붙인다. 서버가 메일의 소유권과 실제
존재를 확인하고 정확한 내용을 GM에게 전달한다. 첨부된 메일의 지시문은 상대의 연락
내용이며 감독의 권한을 부여하지 않는다. 메인 대화는 첨부를 보내거나 제거할 수 있다.

## 2. 발송과 회신

발송은 원문 저장과 회신 대기 업무 등록을 함께 수행하며 게임 시계를 강제로 넘기지 않는다.
회신은 게임 날짜가 진행되어 예정 시점에 도달했을 때 처리한다. 열람·새로고침이나 실제
시간 대기는 새 답변을 만들지 않는다. 대기 중 추가 메일은 같은 상대의 미처리 연락으로
함께 읽되 처리 중 도착한 새 연락을 잃지 않는다.

회신 작업은 메인 GM과 같은 모델 설정과 세계 규칙을 사용하고 해당 스레드·인물·최신
장부를 좁혀 읽는다. 별도 사용자 대화방이나 협상 건별 상주 에이전트는 만들지 않는다.
상대의 제안·거절과 실제 회신은 함께 검증·저장하며 실패 시 부분 상태를 남기지 않는다.
동일 업무를 재실행해도 메일과 제안은 중복되지 않는다. 회신에는 현재의 소속·건강·재정·
다른 제안 등 새 사실을 반영하고 감독의 수락이나 서명을 대신하지 않는다.

훈련·검사 등 코어가 확정한 업무 결과는 관련 보고서 메일로 전달한다. 중요한 새 연락과
협상 현황은 메인 GM이 조회·참조할 수 있다. 전화나 면담에서 이미 진행한 사항도 같은
장부에서 읽으므로 메일과 별도의 협상 상태가 생기지 않는다.
