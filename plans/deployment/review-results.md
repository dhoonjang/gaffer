# 배포 설계 교차 검토와 합성 결과

## 검토 방식

Codex가 원래 수백 명 조건의 설계를 먼저 작성한 뒤, 옆의 실제 Claude Code 에이전트에 [같은 공통 입력](input.md)과 저장소를 전달했다. Claude는 독립안을 작성한 뒤 Codex 안을 읽었다. 진행 중 사용자가 초대제·최소 비용, 이어서 **초기 동시 접속 10명 이하·무료 우선**으로 조건을 좁혔다. 공통 입력을 갱신하고 양쪽 모두 최신 조건에서 재평가했다.

초기 독립안은 비교 근거로 보존한다. Codex의 AWS 다중 AZ 안과 Claude의 유료 서울 VM 안 모두 현재 권장안이 아니다. 최종 선택은 [final-design.md](final-design.md)의 **Cloud Run min 0 + Supabase Free + R2**이며, 짧은 명령의 직접 실행과 독립 일일 백업을 결합한다.

## 비용과 품질의 경계

무료 목표는 유휴 서버·관리형 무료량·전송·보관 비용을 줄이는 것이다. 사용자 경험을 위해 짧은 요청은 직접 실행하고, 모델 품질은 그대로 둔다. LLM 대기·중복 호출·사고 토큰·quota 초과는 별도 영구 원장으로 관리한다. 무료 인프라를 이용해도 LLM까지 무료가 되지는 않는다.

모든 검토 의견을 합의로 꾸미지 않는다. 최신 객체 자동 롤포워드, Tier 2 일괄 필수, 역사적 토큰에 기반한 총비용 단정은 위 이유로 채택하지 않았다. 일반적인 법률 수치·등급분류 단정은 이 기술 설계의 검증 범위를 벗어나 최종안에 옮기지 않았다.

## 확인 범위

- 코드·문서 대조, 격리된 합성 게임/경기 측정, 허용된 개발 로그 metadata 집계, 공식 공급자 문서 확인.
- 문서 포맷과 상대 링크 검사. 애플리케이션 코드 변경·실제 인프라 배포·계정 생성·유료 모델 호출·전체 테스트·e2e·커밋·푸시 없음.
- 최종 설계는 구현 가능한 계약과 출시 게이트다. 실제 클라우드 부하 시험이나 복원 시험을 통과했다는 의미가 아니다.

Claude의 최종 반영 확인은 [claude-review.md](claude-review.md) §8.5.1을 따른다. 당시 Next 기반 검토본에 치명·높음 차단은 없다는 판정을 받았다. 마지막 중간 항목 중 복원 훈련의 무료 프로젝트 한도, 즉시 경로와 어긋난 목표 문장, 이중 콜드 스타트 시나리오, 백업 연결/권한 검증, web 메모리 검증은 최종안에 추가 반영했다. 역사적 토큰으로 계산한 비용 하한 병기는 기존 불확실성 설명으로 대신하고 실제 청구 계측을 출시 조건으로 유지했다.

## 후속 프레임워크 설명의 검토 범위

사용자가 Next 필수 여부와 React/Nest 조합, 작업 실행기의 필요성을 질문하여 [전체 인프라 설명](infrastructure-overview.md)과 상세 설계 §3을 React/Vite + Nest 기준으로 정리했다. 소유권·job/receipt·lease/fence·예산·저장·백업 계약은 유지한다. API/worker/sim의 역할별 배포도 유지하되 물리적 분리가 정확성의 필수조건인 것처럼 설명하지 않는다. Pages 동일 origin 프록시와 OAuth/쿠키·프론트/API 배포 경계는 새 제안이며, 이 부분까지 이전 Claude 완료 판정이 적용됐다고 주장하지 않는다.
